01 — WINDOWS FÍSICO -> KALI VM COM XAMPP: PASSO A PASSO
===============================================================================
CENÁRIO: arquivos do desafio estão no Windows físico e você quer analisá-los na Kali.

NO WINDOWS — descobrir os endereços:
  ipconfig
  ipconfig /all
  route print

O QUE SIGNIFICA:
- ipconfig mostra IPv4 de cada interface.
- ipconfig /all mostra detalhes, gateway, DNS e adaptadores virtuais.
- route print mostra as rotas. Atenção: o Windows pode ter IP de Ethernet,
  Wi-Fi e adaptadores VMware/VirtualBox; o IP certo é o que a Kali alcança.

NA KALI — descobrir rede e rota:
  ip -br addr
  ip route
  hostname -I

O QUE SIGNIFICA:
- ip -br addr lista interfaces e IPs resumidamente.
- ip route revela a rota padrão e redes locais.
- hostname -I mostra IPs atribuídos à máquina.

TESTAR CONECTIVIDADE (substitua o IP):
  ping -c 4 <IP_WINDOWS>
  curl -I http://<IP_WINDOWS>/
  curl -v http://<IP_WINDOWS>/ctf/teste.txt

IMPORTANTE: ping pode falhar porque ICMP está bloqueado; curl testa o HTTP.
"Connection refused" = porta sem serviço; "timed out" = caminho/firewall;
"404" = servidor acessível, mas arquivo/caminho incorreto; "403" = acesso negado.

NO WINDOWS — XAMPP:
1. Abra XAMPP Control Panel e clique Start ao lado de Apache.
2. Teste http://localhost/ no navegador do Windows.
3. Crie C:\xampp\htdocs\ctf\
4. Copie para essa pasta apenas os arquivos de desafio permitidos.
   Exemplo: C:\xampp\htdocs\ctf\captura.pcapng
5. Verifique se http://localhost/ctf/captura.pcapng responde.
6. Se Apache usa 8080 em vez de 80, inclua :8080 na URL.
7. Não altere o firewall nem exponha dados sensíveis sem autorização.

NA KALI — BAIXAR OS ARQUIVOS:
  mkdir -p ~/ctf
  cd ~/ctf
  wget http://<IP_WINDOWS>/ctf/captura.pcapng
  wget http://<IP_WINDOWS>/ctf/imagem.png
  wget http://<IP_WINDOWS>/ctf/desafio.zip
  curl -fLO http://<IP_WINDOWS>/ctf/arquivo.bin
  ls -lah
  file *

O QUE SIGNIFICA:
- mkdir -p cria pasta sem erro se já existe.
- cd muda para a pasta.
- wget baixa o arquivo para a pasta atual.
- curl -fLO falha em HTTP 4xx/5xx, usa nome remoto e segue redirecionamentos.
- ls -lah mostra arquivos, tamanhos e ocultos.
- file * identifica o tipo real de cada arquivo.

VALIDAR CÓPIA (integridade):
  # Windows CMD:
  certutil -hashfile C:\xampp\htdocs\ctf\captura.pcapng SHA256
  # Kali:
  sha256sum ~/ctf/captura.pcapng
Se os hashes forem iguais, o conteúdo foi transferido sem alteração.

DIAGNÓSTICO EXTRA:
  # Windows:
  netstat -ano | findstr :80
  # Kali:
  curl -I http://<IP_WINDOWS>:8080/
  ip route get <IP_WINDOWS>

Se não houver conexão, verifique modo de rede da VM (NAT, host-only, bridge)
e peça ao responsável do laboratório a configuração permitida.

ATENÇÃO SOBRE O DIRETÓRIO: Apache normalmente NÃO lista arquivos da pasta
quando a listagem está desabilitada. Use o nome exato na URL; não dependa de
abrir http://<IP_WINDOWS>/ctf/ e ver uma lista.

02 — IDENTIFICAR ARQUIVO, PROTEGER ORIGINAL E TRIAGEM
===============================================================================
  pwd                         # pasta atual
  ls -lah                     # lista detalhada, inclusive ocultos
  file arquivo                # tipo real
  stat arquivo                # tamanho, datas e metadados do sistema
  sha256sum arquivo           # impressão digital SHA-256
  strings -a arquivo | head -n 60   # textos legíveis no binário
  xxd -l 128 arquivo          # primeiros 128 bytes em hexadecimal
  hexdump -C arquivo | head   # outra visão hexadecimal
  find . -type f              # todos os arquivos abaixo da pasta
  find . -iname '*flag*'      # nomes contendo flag (sem diferenciar caixa)
  grep -RniE 'flag|ctf|fiap' .  # texto recursivo, com linha e nome do arquivo

WINDOWS:
  dir /a
  where python
  certutil -hashfile arquivo SHA256
  findstr /spin /c:"flag" *.*
POWERSHELL:
  Get-ChildItem -Force
  Get-FileHash .\arquivo -Algorithm SHA256
  Get-ChildItem -Recurse -File | Select-String -Pattern 'flag','ctf','fiap'

OBS: procurar a palavra "flag" nem sempre basta. Leia o enunciado para saber
o formato e a evidência exigida. Não confunda strings ocasionais com prova.

03 — PCAP / PCAPNG: O QUE FAZER
===============================================================================
GUIA:
1. Abra a captura no Wireshark; Statistics > Protocol Hierarchy e Conversations.
2. Procure DNS, HTTP, FTP, SMTP e tráfego incomum.
3. Use Follow > TCP Stream / UDP Stream para reconstruir conversas.
4. Em File > Export Objects > HTTP, veja se houve transferência de arquivos.
5. Correlacione IPs, horários e nomes de domínio.

WIRESHARK — FILTROS DE EXIBIÇÃO (na barra de filtro):
  dns
  http
  http.request
  tcp
  tls
  ftp
  smtp
  ip.addr == 192.168.56.101
  tcp.port == 80
  dns.qry.name contains "exemplo"
  frame contains "flag"
  tcp contains "flag"
  http.request.method == "POST"
  tcp.analysis.retransmission

O QUE SIGNIFICA:
- dns mostra consultas e respostas DNS.
- http.request mostra requisições HTTP.
- ip.addr mostra tráfego de/para aquele IP.
- frame contains busca sequência de bytes no pacote.
- Follow TCP Stream é frequentemente mais útil do que olhar pacotes isolados.

TSHARK — COMANDOS PRONTOS:
  tshark -r captura.pcapng -q -z io,phs
  tshark -r captura.pcapng -q -z conv,ip
  tshark -r captura.pcapng -Y dns -T fields -e frame.time -e ip.src -e dns.qry.name
  tshark -r captura.pcapng -Y http.request -T fields -e ip.src -e http.host -e http.request.uri
  tshark -r captura.pcapng -Y 'tcp.port == 80' -T fields -e tcp.stream | sort -nu
  tshark -r captura.pcapng -q -z follow,tcp,ascii,0

EXPLICAÇÃO:
- -r lê arquivo salvo (não captura ao vivo).
- -Y aplica filtro de exibição.
- -T fields escolhe saída em colunas.
- -e seleciona um campo, como dns.qry.name.
- -z conv,ip mostra conversas entre IPs.
- -z follow,tcp,ascii,0 reconstrói o fluxo TCP índice 0 (troque o número).

TCPDUMP — VER RESUMO:
  tcpdump -nn -r captura.pcapng
  tcpdump -nn -r captura.pcapng 'port 53'
  tcpdump -nn -r captura.pcapng 'host 192.168.56.101'
-nn evita resolver nomes/portas; -r lê o arquivo.

SNORT — ANÁLISE OFFLINE (sintaxe pode variar por versão):
  snort -V
  snort -r captura.pcap -A console -c /etc/snort/snort.conf
Se a configuração não existir, verifique a instalação/versão; não invente
caminhos. Regras Snort 2 e Snort 3 têm diferenças de configuração.

REGRA SIMPLES DE EXEMPLO (em laboratório):
  alert tcp any any -> any 80 (msg:"CTF HTTP"; sid:1000001; rev:1;)
Significa: alertar tráfego TCP destinado à porta 80; sid identifica a regra.
Ela é propositalmente ampla: não prova atividade maliciosa.

  file imagem.png

06 — MALWARE: TRIAGEM ESTÁTICA SEM EXECUTAR
===============================================================================
  file amostra.exe
  sha256sum amostra.exe
  strings -a -n 6 amostra.exe | head -n 100
  strings -a amostra.exe | grep -iE 'http|https|powershell|cmd.exe|AppData|Run\\'
  objdump -x amostra.exe | head -n 100
  xxd -l 128 amostra.exe

WINDOWS/POWERSHELL:
  Get-FileHash .\amostra.exe -Algorithm SHA256
  Get-Item .\amostra.exe | Format-List *
  Get-AuthenticodeSignature .\amostra.exe

O QUE PROCURAR:
- URLs, IPs, nomes de mutex, chaves Run, caminhos AppData/Temp.
- Imports e APIs relacionadas a rede, processos e persistência.
- Strings em UTF-16LE: strings comum pode não encontrá-las.
- EncodedCommand e FromBase64String em scripts PowerShell.
- Um IOC isolado não é prova suficiente; correlacione com outros artefatos.

NÃO rode malware na máquina física; peça VM isolada/autorizada.

08 — LOGS COM AWK / GREP / SED / SORT / UNIQ / JQ
===============================================================================
  head -n 20 access.log
  tail -n 30 access.log
  grep -niE 'error|failed|denied' access.log
  awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
  awk '{print $9}' access.log | sort | uniq -c | sort -nr
  grep ' 404 ' access.log | head
  sed -n '10,30p' access.log
  jq '.' resposta.json
  jq -r '.items[]?.name' resposta.json

EXPLICAÇÃO:
- head/tail: começo/fim do arquivo.
- grep -n: mostra número da linha; -i ignora maiúsculas; -E usa regex.
- awk '{print $1}': primeira coluna (frequentemente IP no log combinado).
- sort | uniq -c: agrupa e conta; sort -nr: maiores contagens primeiro.
- awk '{print $9}': status HTTP SOMENTE se o log segue formato combinado.
- sed -n '10,30p': mostra linhas 10 a 30.
- jq: lê JSON; -r remove aspas de strings; ? evita alguns erros de ausência.

NÃO suponha o formato do log. Primeiro use head e identifique as colunas.

---------------------------------------------------------
1. COMO PENSAR DURANTE O CTF
---------------------------------------------------------

Quando receber um desafio:

1) Leia o texto inteiro e destaque palavras importantes.
2) Identifique o tipo: rede/PCAP, web, criptografia, forense, imagem, malware,
   Linux, Windows, engenharia reversa ou combinação.
3) Veja quais arquivos e informações foram fornecidos.
4) Faça uma hipótese simples e teste uma coisa por vez.
5) Anote comando, resultado e próxima hipótese.
6) Se não funcionar, não repita igual: mude a abordagem.
7) Procure a flag e valide o formato pedido.

Exemplo de anotação:
Desafio: captura de rede
Pista: “conversa suspeita”
Hipótese: há comunicação HTTP ou DNS
Ação: abrir PCAP no Wireshark; olhar Protocol Hierarchy; filtrar http/dns
Resultado: IP e domínio encontrados
Próximo passo: seguir fluxo TCP e verificar conteúdo

---------------------------------------------------------
2. LINUX E TERMINAL — EXPLICAÇÃO DOS COMANDOS
---------------------------------------------------------

O terminal permite navegar, localizar arquivos, ler conteúdo e executar ferramentas.

NAVEGAR
--------
pwd
Mostra o diretório em que você está.
Use quando não souber onde está trabalhando.

ls
Lista arquivos e pastas.

ls -la
Lista também arquivos ocultos (nomes que começam com ponto), permissões,
proprietário e tamanho. Muito útil porque pistas podem estar em .arquivo.

cd pasta
Entra na pasta.

cd ..
Volta um nível.

mkdir analise
Cria uma pasta para organizar o trabalho.

cp arquivo arquivo.bak
Copia um arquivo. Use cópias para preservar o original.

IDENTIFICAR E LER
-----------------
file arquivo
Identifica o tipo real do arquivo, mesmo se a extensão estiver errada.
Exemplo: algo.jpg pode ser, na verdade, um ZIP ou arquivo de texto.

cat arquivo.txt
Mostra o conteúdo inteiro. Melhor para arquivos pequenos.

less arquivo.txt
Abre leitura paginada. Use setas/PageUp/PageDown e pressione q para sair.

head -n 20 arquivo.txt
Mostra as primeiras 20 linhas.

tail -n 20 arquivo.txt
Mostra as últimas 20 linhas.

wc -l arquivo.txt
Conta linhas. Também pode ajudar a medir arquivos.

PESQUISAR
----------
grep -ni "flag" arquivo.txt
Procura “flag” ignorando maiúsculas/minúsculas e mostra números das linhas.

grep -RniE 'flag|password|token|secret' .
Procura palavras comuns em arquivos da pasta atual e subpastas.
-R = recursivo; -n = linha; -i = ignora maiúsculas/minúsculas.
Pode retornar muita coisa; filtre por diretório ou extensão se necessário.

find . -type f
Lista arquivos, inclusive em subpastas.

find . -type f -name "*.txt"
Procura apenas arquivos TXT.

find . -type f -size +1M
Procura arquivos maiores que 1 MB.

strings arquivo.bin
Mostra trechos de texto legíveis encontrados em um arquivo binário.
Use quando o arquivo não abre como texto, mas pode conter mensagens, URLs ou flags.

xxd arquivo | head
Mostra bytes em hexadecimal e uma coluna de texto aproximada.
Use para identificar cabeçalhos ou conteúdo codificado.

ARQUIVOS COMPACTADOS
---------------------
unzip -l arquivo.zip
Lista o que existe no ZIP sem extrair.

unzip arquivo.zip
Extrai o conteúdo.

tar -tf arquivo.tar
Lista arquivos dentro de TAR.

tar -xvf arquivo.tar
Extrai TAR.

7z l arquivo.7z
Lista conteúdo 7z.

7z x arquivo.7z
Extrai 7z, se o programa estiver instalado.

DICA: Se a extração pedir senha, procure pistas no enunciado, nome do arquivo,
outros artefatos e metadados. Não tente adivinhar aleatoriamente sem estratégia.

---------------------------------------------------------
3. WIRESHARK — GUIA PASSO A PASSO
---------------------------------------------------------

O Wireshark analisa capturas de rede (PCAP/PCAPNG). Ele mostra os pacotes
e permite filtrar protocolos, IPs, portas e conteúdo.

ABRIR A CAPTURA
----------------
1) Abra o Wireshark.
2) File > Open.
3) Selecione o arquivo .pcap ou .pcapng.
4) Aguarde carregar.
5) Observe os protocolos e endereços na lista.

AS TRÊS ÁREAS
---------------
Packet List:
Lista de pacotes. Cada linha é uma comunicação capturada.

Packet Details:
Ao selecionar pacote, mostra camadas, por exemplo:
Ethernet > IP > TCP > HTTP.

Packet Bytes:
Mostra os bytes em hexadecimal e texto ASCII quando legível.

COMO LER UM PACOTE
-------------------
Clique em um pacote.
Expanda as setas das camadas:
- Ethernet: endereços MAC
- Internet Protocol (IP): IP de origem e destino
- TCP/UDP: portas
- DNS/HTTP: dados do protocolo

Perguntas úteis:
- Quem iniciou a comunicação?
- Qual IP aparece repetidamente?
- Qual serviço/porta está sendo usado?
- Existe nome de domínio?
- Há dados de texto, arquivo ou credencial de laboratório?

FILTROS DE EXIBIÇÃO
--------------------
Digite na barra de filtro e pressione Enter.
Eles só escondem/mostram pacotes; não apagam a captura.

dns
Mostra tráfego DNS. Use para descobrir domínios consultados.

http
Mostra HTTP sem criptografia. Pode revelar requisições e respostas.

tls
Mostra tráfego TLS. O conteúdo costuma estar criptografado, mas metadados podem
ajudar, como IPs, certificados e nomes disponíveis na captura.

tcp
Mostra TCP.

udp
Mostra UDP.

icmp
Mostra ICMP, frequentemente usado por ping.

arp
Mostra resolução de endereços na rede local.

ip.addr == 192.168.1.10
Mostra pacotes em que o IP aparece como origem OU destino.

ip.src == 192.168.1.10
Mostra somente pacotes originados nesse IP.

ip.dst == 192.168.1.10
Mostra somente pacotes destinados a esse IP.

tcp.port == 80
Mostra TCP com porta 80.

udp.port == 53
Mostra UDP com porta 53, comum para DNS.

http.request
Mostra requisições HTTP.

dns.qry.name
Filtro para campo de nome consultado em DNS; use junto de dns, por exemplo:
dns && dns.qry.name

tcp.flags.syn == 1
Mostra pacotes com flag SYN. Pode ajudar a observar tentativas de conexão.

frame contains "flag"
Procura bytes/texto “flag” no pacote, quando o conteúdo está visível.

tcp contains "password"
Procura texto password dentro de segmentos TCP; pode não funcionar se o conteúdo
estiver criptografado ou dividido em segmentos.

Combinar:
ip.addr == 192.168.1.10 && tcp
Mostra TCP envolvendo aquele IP.

dns || http
Mostra DNS ou HTTP.

!(arp or icmp)
Esconde ARP e ICMP.

OBSERVAÇÃO: IPs acima são exemplos. Troque pelos endereços vistos no desafio.

FOLLOW TCP STREAM — MUITO IMPORTANTE
-------------------------------------
1) Selecione um pacote TCP.
2) Clique com o botão direito.
3) Follow > TCP Stream.
4) O Wireshark reúne os dados daquele fluxo em uma conversa.
5) Observe texto enviado e recebido.
6) Use o seletor de fluxo para navegar em outras conversas.
7) Feche a janela e continue investigando.

Por que isso ajuda?
Pacotes separados podem parecer incompreensíveis. O Follow Stream organiza a
conversa e pode revelar:
- URLs e parâmetros
- Mensagens HTTP
- Dados enviados pelo cliente
- Respostas do servidor
- Texto que contenha uma pista ou flag

Se aparecer conteúdo ilegível, pode estar comprimido, codificado ou criptografado.
Não conclua que não há informação: examine outros fluxos e protocolos.

ESTATÍSTICAS
-------------
Statistics > Protocol Hierarchy
Mostra quais protocolos aparecem e a quantidade. Bom para começar a captura.

Statistics > Conversations
Mostra pares de IPs/portas e volume de dados. Ajuda a descobrir quem conversou
com quem e quais fluxos parecem relevantes.

Statistics > Endpoints
Lista hosts vistos. Ajuda a identificar IPs internos/externos.

Statistics > DNS
Pode resumir consultas DNS, dependendo da versão e captura.

EXPORTAR ARQUIVOS
-----------------
File > Export Objects > HTTP
Se houver objetos HTTP recuperáveis, permite salvar arquivos transferidos.
Depois use file, strings, exiftool ou outras ferramentas para analisar.

FILTRO DE CAPTURA X FILTRO DE EXIBIÇÃO
----------------------------------------
Filtro de exibição:
- Usado depois que os pacotes já foram capturados.
- Exemplo: http
- Sintaxe: ip.addr == 10.0.0.5

Filtro de captura:
- Usado antes/durante a captura para limitar o que será registrado.
- Exemplos: host 10.0.0.5, port 53, tcp, udp
- Sintaxe diferente da barra de display filters.

4. TSHARK — WIRESHARK NO TERMINAL
---------------------------------------------------------

tshark -r captura.pcap
Lê a captura pelo terminal.

tshark -r captura.pcap -Y dns
Exibe apenas pacotes que combinam com o filtro DNS.

tshark -r captura.pcap -Y http
Exibe HTTP.

tshark -r captura.pcap -Y "ip.addr == 10.0.0.5"
Filtra por IP.

tshark -r captura.pcap -c 20
Limita a saída a 20 pacotes.

tshark -r captura.pcap -T fields -e ip.src -e ip.dst -e dns.qry.name
Mostra campos escolhidos: IP de origem, destino e nome DNS.
Se algum campo não existir no pacote, ficará vazio.

-Y é filtro de exibição.
-r indica arquivo de captura.
-c limita número de pacotes.
-T fields escolhe formato de campos.

5. REDE E NMAP — ENUMERAÇÃO
---------------------------------------------------------

Enumeração significa descobrir quais hosts/serviços existem no ambiente.
No CTF, use somente o IP ou rede autorizada.

ip a
Mostra interfaces de rede e endereços IP locais.

ip route
Mostra rotas e gateway.

ping -c 4 IP
Envia quatro solicitações ICMP para testar conectividade. Alguns hosts bloqueiam
ping, então ausência de resposta não prova que o host está desligado.

nslookup dominio
Consulta DNS.

dig dominio
Consulta DNS com mais detalhes.

curl -I http://ALVO
Faz requisição HTTP HEAD e mostra cabeçalhos.

curl -i http://ALVO
Mostra cabeçalhos e corpo da resposta.

NMAP
----
nmap -sV -sC IP
Verifica serviços e versões e executa scripts padrão no alvo autorizado.
-sV tenta identificar versões.
-sC usa scripts padrão.

nmap -p 22,80,443 IP
Verifica somente portas escolhidas.

nmap -p- IP
Verifica todas as portas TCP. Pode levar tempo e gerar tráfego; use apenas se
o escopo permitir.

nmap -oN resultado.txt IP
Salva resultado em texto normal.

COMO INTERPRETAR
----------------
Porta 22: frequentemente SSH.
Porta 80: frequentemente HTTP.
Porta 443: frequentemente HTTPS.
Porta 21: frequentemente FTP.
Porta 25: frequentemente SMTP.
Porta 53: DNS.
Porta 3306: frequentemente MySQL.
Porta 5432: frequentemente PostgreSQL.
Porta 3389: frequentemente RDP.
Porta 8080: HTTP alternativo/painel.

Porta aberta não significa vulnerabilidade automaticamente.
Identifique serviço, versão, banner e pistas do desafio antes de concluir.

- texto comum?

- resposta refletida?
Não teste em sites reais nem em usuários terceiros.

---------------------------------------------------------
7. BASE64, HEX, ROT13, HASH E JWT
---------------------------------------------------------

BASE64
------
Base64 é codificação, não criptografia. Pode ser revertida sem chave.

echo 'SGVsbG8=' | base64 -d
Resultado: Hello

echo 'Hello' | base64
Codifica texto para Base64.

Pistas:
- Letras, números, +, / e às vezes = no final.
- Pode aparecer em arquivos, URLs, tokens e capturas.
- Se decodificar e sair texto estranho, veja se há outra camada.

HEX
---
xxd arquivo
Mostra bytes em hexadecimal.

echo '48656c6c6f' | xxd -r -p
Converte hex em bytes; exemplo resulta em Hello.

ROT13
-----
tr 'A-Za-z' 'N-ZA-Mn-za-m'
Aplica ROT13 a texto digitado via pipe.
ROT13 troca cada letra pela que está 13 posições à frente.
Aplicar novamente reverte.

HASH
----
sha256sum arquivo
Calcula SHA-256.

md5sum arquivo
Calcula MD5.

Hash é uma impressão digital; não é decodificado como Base64.
Se o desafio fornece hash de senha, procure pista sobre algoritmo e formato.
Use ferramentas de cracking somente com hash fornecido no CTF e dentro das regras.

JWT
---
Um JWT costuma ter três partes separadas por ponto:
header.payload.signature

Header e payload podem ser Base64URL.
Decodificar payload permite ler claims, mas não valida assinatura nem autoriza acesso.
Nunca coloque tokens pessoais em sites públicos de decodificação.

9. IMAGENS E ESTEGANOGRAFIA
---------------------------------------------------------

Esteganografia tenta esconder informação dentro de outro arquivo, por exemplo imagem.

PASSO A PASSO
--------------
1) file imagem.png
   Confirme o formato real.

2) exiftool imagem.png
   Procure comentários e metadados.

3) strings imagem.png
   Procure texto visível.

4) binwalk imagem.png
   Veja se há conteúdo embutido.

5) Se PNG/BMP e pistas apontarem para esteganografia, tente zsteg.

6) Se JPEG e o desafio indicar steghide:
   steghide info imagem.jpg
   steghide extract -sf imagem.jpg
   Pode solicitar uma senha. Procure pistas no enunciado/arquivos.

Ferramentas podem não estar instaladas. Não gaste tempo tentando usar comando
ausente; use alternativa disponível ou peça ajuda no ambiente.

14. COMANDOS PRONTOS — LINUX (COPIAR, ALTERAR E EXECUTAR)
=========================================================

Como usar esta seção:
- Copie o comando.
- Troque somente o que estiver entre <...> pelos dados do desafio.
- Remova os sinais < > ao substituir.
- Se um caminho tiver espaços, coloque-o entre aspas.
- Antes de executar, confira se está na pasta correta com pwd e ls.
- Alguns comandos podem não estar instalados no ambiente. Se aparecer
  “command not found”, pule para outra ferramenta disponível.

DICA: para facilitar, defina variáveis no terminal. Depois você troca o valor
uma vez e reutiliza nos comandos.

A) DEFINIR CAMINHOS E NOMES
-----------------------------
ARQUIVO="/caminho/para/arquivo.pcap"
PASTA="/caminho/para/pasta"
ALVO="10.10.10.10"
URL="http://10.10.10.10"

Exemplo realista de caminho:
ARQUIVO="$HOME/Downloads/captura.pcap"

Verifique:
echo "$ARQUIVO"
ls -lh "$ARQUIVO"
file "$ARQUIVO"

IMPORTANTE: essas variáveis valem apenas no terminal atual. Se abrir outro terminal,
defina-as novamente.

B) IDENTIFICAR QUALQUER ARQUIVO
-------------------------------
file "<CAMINHO_DO_ARQUIVO>"
Exemplo:
file "$HOME/Downloads/desafio.bin"

Ver tamanho:
ls -lh "<CAMINHO_DO_ARQUIVO>"

Ver metadados básicos:
stat "<CAMINHO_DO_ARQUIVO>"

Calcular SHA-256:
sha256sum "<CAMINHO_DO_ARQUIVO>"

C) PROCURAR FLAGS E PALAVRAS EM UMA PASTA
-------------------------------------------
grep -RniE 'FLAG\{|FIAP\{|flag|password|token|secret' "<PASTA_DO_DESAFIO>" 2>/dev/null

Exemplo:
grep -RniE 'FLAG\{|FIAP\{|flag|password|token|secret' "$HOME/Downloads/ctf" 2>/dev/null

Procurar somente arquivos TXT:
find "<PASTA_DO_DESAFIO>" -type f -name "*.txt"

Procurar arquivos ocultos:
find "<PASTA_DO_DESAFIO>" -type f -name ".*"

D) EXTRAIR STRINGS DE ARQUIVO SUSPEITO
---------------------------------------
strings -n 5 "<ARQUIVO>" | less

Salvar strings em outro arquivo:
strings -n 5 "<ARQUIVO>" > strings.txt

Procurar flag nas strings:
strings -n 5 "<ARQUIVO>" | grep -iE 'FLAG\{|FIAP\{|flag'

E) HEXADECIMAL
--------------
Mostrar bytes:
xxd "<ARQUIVO>" | head -n 40

Converter texto hexadecimal para arquivo:
xxd -r -p "<ARQUIVO_HEX>" > resultado.bin

Se o hex estiver escrito em uma linha de texto:
echo '<HEX_AQUI>' | xxd -r -p

F) BASE64
----------
Decodificar arquivo Base64:
base64 -d "<ARQUIVO_BASE64>" > decodificado.bin

Decodificar texto Base64:
echo '<BASE64_AQUI>' | base64 -d

Codificar texto:
echo -n '<TEXTO_AQUI>' | base64

Se a saída parecer outro formato, rode:
file decodificado.bin
strings decodificado.bin | head

G) ZIP / TAR
-------------
Listar ZIP:
unzip -l "<ARQUIVO.zip>"

Extrair ZIP para pasta:
mkdir -p "<PASTA_DESTINO>"
unzip "<ARQUIVO.zip>" -d "<PASTA_DESTINO>"

Listar TAR:
tar -tf "<ARQUIVO.tar>"

Extrair TAR:
mkdir -p "<PASTA_DESTINO>"
tar -xf "<ARQUIVO.tar>" -C "<PASTA_DESTINO>"

H) WIRESHARK / PCAP
-------------------
Abrir PCAP no Wireshark:
wireshark "<ARQUIVO.pcap>"

Ver DNS no terminal:
tshark -r "<ARQUIVO.pcap>" -Y dns

Ver HTTP:
tshark -r "<ARQUIVO.pcap>" -Y http

Ver tráfego de um IP:
tshark -r "<ARQUIVO.pcap>" -Y "ip.addr == <IP>"

Exemplo:
tshark -r "$HOME/Downloads/captura.pcap" -Y "ip.addr == 10.10.10.10"

Mostrar origem, destino e DNS:
tshark -r "<ARQUIVO.pcap>" -T fields -e ip.src -e ip.dst -e dns.qry.name

Mostrar pacotes com texto flag:
tshark -r "<ARQUIVO.pcap>" -Y 'frame contains "flag"'

Exportar lista de conversas TCP:
tshark -r "<ARQUIVO.pcap>" -q -z conv,tcp

I) NMAP — ALVO DO CTF
----------------------
Ver serviços e versões:
nmap -sV -sC "<IP_DO_ALVO>"

nmap -p 22,80,443 "<IP_DO_ALVO>"

nmap -sV -sC -oN "<ARQUIVO_DE_SAIDA.txt>" "<IP_DO_ALVO>"

Exemplo:
nmap -sV -sC -oN scan.txt 10.10.10.10

curl -s "<URL_DO_DESAFIO>" | grep -iE 'flag|secret|token'

curl -i "<URL_DO_DESAFIO>/robots.txt"

P) SERVIDOR HTTP TEMPORÁRIO PARA COMPARTILHAR ARQUIVO
-------------------------------------------------------
Se os dois computadores estiverem em uma rede que permita comunicação e a
política da FIAP autorizar:

1. No computador que tem o arquivo, entre na pasta dele:
   cd "<PASTA_QUE_CONTEM_O_ARQUIVO>"

2. Inicie servidor:
   python3 -m http.server 8000

3. Descubra o IP do computador:
   ip a

4. No outro computador, abra:
   http://<IP_DO_COMPUTADOR>:8000/<NOME_DO_ARQUIVO>

5. Ao terminar, volte ao terminal do servidor e pressione:
   Ctrl+C

A rede pode bloquear conexões entre dispositivos; isso não significa que o comando
esteja errado. Não exponha o servidor à internet nem compartilhe arquivos privados.
Para a prova, prefira Drive, e-mail institucional ou pendrive permitido.

Q) XAMPP NO LINUX (SE JÁ ESTIVER INSTALADO)
---------------------------------------------
Pasta web padrão:
  /opt/lampp/htdocs

Copiar arquivo para uma pasta do site:
  sudo mkdir -p /opt/lampp/htdocs/ctf
  sudo cp "<CAMINHO_DO_TXT>" /opt/lampp/htdocs/ctf/guia.txt

Iniciar Apache/XAMPP:
  sudo /opt/lampp/lampp start

Parar XAMPP:
  sudo /opt/lampp/lampp stop

Acessar no próprio computador:
  http://127.0.0.1/ctf/guia.txt

Para outro computador, use:
  http://<IP_DO_COMPUTADOR>/ctf/guia.txt

Isso depende de Apache ativo, IP acessível, firewall/rede permitindo e autorização.
Não abra portas do roteador nem exponha o computador pessoal à internet só para
a prova. Em rede campus, o acesso entre dispositivos pode ser bloqueado.

R) QUANDO O COMANDO DÁ ERRO
----------------------------
“command not found”

18. NMAP: RECONHECIMENTO EM ALVOS DO CTF
======================================================================
Comece pelo escopo. Exemplos só para IPs explicitamente fornecidos:
  nmap -sT -sV --open <IP>
    -sT: conexão TCP normal; -sV: tenta identificar versão do serviço.
  nmap -Pn -sT -sV -p 22,80,443,445,8080 <IP>
    -Pn: não depende de resposta ao ping; -p: portas específicas.
  nmap -p- --open -T3 <IP>
    examina todas as portas TCP; use só se permitido e necessário.
  nmap -sC -sV -p 80,443 <IP>
    scripts padrão + versão nas portas indicadas.
  nmap -sU -p 53,161 <IP>
    testa UDP, geralmente mais lento; resultados podem ser inconclusivos.
  nmap -oN scan.txt -sV <IP>
    salva relatório legível.
  nmap -oA scan_ctf -sV <IP>
    salva formatos .nmap, .xml e .gnmap.

LEITURA DOS RESULTADOS:
  open = serviço aceitando conexões; closed = rejeitou; filtered = filtro.
  21 FTP, 22 SSH, 25 SMTP, 53 DNS, 80/443 HTTP(S), 139/445 SMB,
  3306 MySQL, 3389 RDP, 5432 PostgreSQL, 8080/8000 web alternativa.
  Porta aberta NÃO prova vulnerabilidade. Enumere serviço e versão antes.
  Se Nmap não existir: 'nc -vz <IP> <PORTA>' (Linux, se nc existir)
  ou 'Test-NetConnection -ComputerName <IP> -Port <PORTA>' (PowerShell).

19. METASPLOIT FRAMEWORK — GUIA DE LABORATÓRIO
======================================================================
Metasploit é um framework de módulos auxiliares, exploits e pós-exploração.
Use SOMENTE contra máquinas do desafio explicitamente autorizadas.

PRIMEIROS PASSOS:
  msfconsole -q                  abre console sem banner
  help                           lista comandos
  search type:auxiliary smb      procura módulos auxiliares SMB
  search name:eternalblue        procura módulos por nome
  search type:exploit platform:windows  filtra por plataforma
  info <NOME_DO_MODULO>          documentação e requisitos
  use <NOME_DO_MODULO>           seleciona módulo
  show options                   opções obrigatórias e valores atuais
  show advanced                  opções avançadas
  show targets                   alvos suportados, quando aplicável
  show payloads                  payloads compatíveis, quando aplicável
  set RHOSTS <IP>                IP do alvo do CTF
  set RPORT <PORTA>              porta do serviço
  set LHOST <SEU_IP_NO_LAB>      IP da máquina do participante no lab
  check                          testa vulnerabilidade, se módulo suportar
  run                            executa auxiliar/alguns módulos
  exploit                        executa módulo de exploit autorizado
  back                           volta à lista principal
  sessions                       lista sessões do laboratório
  sessions -i <ID>               interage com sessão do lab
  exit                           sai do console

EXEMPLO 1: ENUMERAÇÃO AUXILIAR SEM EXPLOIT
  msfconsole -q
  search type:auxiliary scanner/smb
  use auxiliary/scanner/smb/smb_version
  show options
  set RHOSTS <IP>
  run
  back
Objetivo: identificar implementação/versão SMB; isso NÃO explora o alvo.

EXEMPLO 2: ANALISAR UM MÓDULO ANTES DE QUALQUER EXECUÇÃO
  search name:ms17_010
  info exploit/windows/smb/ms17_010_eternalblue
  use exploit/windows/smb/ms17_010_eternalblue
  show options
  show targets
  show payloads
  set RHOSTS <IP_DO_LAB>
  check
NÃO execute exploit automaticamente: cheque SO, versão, arquitetura,
requisitos, regras do desafio e risco de travar a VM. 'check' pode ser
inconclusivo; nem todo módulo suporta check. Evite payloads persistentes.

SE APARECER 'NO SESSION WAS CREATED':
  - Pode não ser vulnerável, versão incompatível ou opções incorretas.
  - Confira 'show options', RHOSTS/RPORT, arquitetura e conectividade.
  - LHOST deve ser IP alcançável pelo alvo, não '127.0.0.1'.
  - Firewall/NAT podem impedir conexão de retorno.
  - Leia 'info' e procure o caminho menos invasivo permitido.

VOCABULÁRIO:
  exploit = código que aproveita falha; payload = ação após exploração;
  auxiliary = enumeração/testes; session = conexão estabelecida;
  RHOSTS = alvo; RPORT = porta alvo; LHOST = origem para retorno.

20. COMMAND INJECTION — LINUX E WINDOWS (WEB CTF)
======================================================================
Ocorre quando uma aplicação concatena entrada do usuário em um comando de
sistema sem tratamento adequado. Use SOMENTE endpoints de laboratório.

EXEMPLO DE CENÁRIO: formulário 'ping host' que chama comando do sistema.
TESTE MÍNIMO E NÃO DESTRUTIVO:
  127.0.0.1
  127.0.0.1; whoami       (shell Unix, se separador for interpretado)
  127.0.0.1 && id         (Unix, segundo comando só se primeiro funcionar)
  127.0.0.1 | whoami      (pipe Unix; depende do contexto)
  127.0.0.1 & whoami      (CMD Windows: separador de comandos)
  127.0.0.1 && whoami     (CMD Windows: executa se primeiro der certo)

INTERPRETAÇÃO:
  - Se aparecer usuário do processo web, há indício forte de execução.
  - Se o texto for mostrado literalmente, talvez esteja escapado.
  - Erro de sintaxe não prova ausência de falha; contexto importa.
  - Em Linux, 'id', 'pwd', 'uname -a' ajudam a identificar ambiente.
  - Em Windows, 'whoami', 'ver', 'cd' ajudam a identificar ambiente.
  - Não use comandos destrutivos, downloads de payloads ou persistência.

DIFERENÇAS IMPORTANTES:
  Bash: ; separa, && condicional, || se falhar, | pipe, $(...) substituição.
  CMD: & separa, && condicional, || se falhar, | pipe.
  PowerShell: ; separa; && só em PowerShell 7+, não no Windows PowerShell 5.1.
  URL: caracteres como & e # têm significado especial; use URL encoding
  quando o teste for em parâmetros HTTP, por exemplo %26 para '&'.

COMO INVESTIGAR:
  1) Encontre parâmetro que parece chegar ao SO (ping, host, file, path).
  2) Observe saída normal e mensagem de erro.
  3) Compare uma entrada legítima com teste mínimo 'whoami' ou 'id'.
  4) Confirme sistema operacional e contexto.
  5) Leia apenas arquivos indicados pelo desafio e registre evidências.
  6) Se não houver saída visível, analise tempo/erros com cautela;
     não faça tentativas indiscriminadas.

21. WEB CTF: CHECKLIST DE TESTES E INTERPRETAÇÃO
======================================================================
RECONHECIMENTO MANUAL
  - Veja HTML (Ctrl+U), DevTools (F12), abas Network/Storage/Console.
  - Procure comentários HTML, JS, endpoints, source maps, formulários.
  - Veja robots.txt, sitemap.xml, cookies e códigos de resposta.
  - Observe requisições Fetch/XHR e parâmetros ocultos.
  - Faça um teste de cada vez; anote requisição e resposta.

CURL PRÁTICO
  curl -i '<URL>'                    cabeçalhos + corpo
  curl -I '<URL>'                    cabeçalhos apenas (HEAD)
  curl -L -i '<URL>'                 segue redirects
  curl -X POST '<URL>/login' -d 'user=teste&pass=teste'
  curl -H 'Accept: application/json' '<URL>/api'
  curl -b 'session=VALOR' '<URL>'    envia cookie do laboratório
  curl -c cookies.txt '<URL>'       salva cookies recebidos
  curl -b cookies.txt '<URL>'       reutiliza cookies salvos
  curl --data-urlencode 'q=a b' '<URL>/search'
  curl -s '<URL>' | grep -Ei 'flag|TODO|secret|api'
  curl -v '<URL>'                    detalhes da conexão
No PowerShell prefira curl.exe com os mesmos argumentos.

STATUS HTTP
  200 OK; 301/302 redirecionamento; 400 entrada ruim;
  401 não autenticado; 403 proibido; 404 não encontrado;
  405 método não permitido; 500 erro do servidor.
Um 403 não é permissão para tentar burlar regras da competição.

SQL INJECTION: IDENTIFICAÇÃO NO LAB
  - Pistas: parâmetros numéricos, mensagens de banco, resposta alterada.
  - Compare valor normal e entrada com apóstrofo simples: '
  - Erro SQL após apóstrofo sugere consulta mal parametrizada, mas não prova.
  - Observe diferença de resposta e confirme em ambiente do desafio.
  - SQLi é distinta de command injection: uma afeta consulta ao banco;
    outra afeta comando do sistema operacional.
  - Se houver código-fonte, procure concatenação de SQL e uso de parâmetros.

XSS: RECONHECIMENTO
  - Insira um marcador textual único no campo e veja onde ele aparece.
  - Inspecione se o texto entra em HTML, atributo, JavaScript ou URL.
  - Contexto e encoding determinam se há vulnerabilidade.
  - Não use XSS para coletar sessões ou dados de outras pessoas.

PATH TRAVERSAL E LFI: RECONHECIMENTO
  - Pistas: 'file=', 'page=', 'template=', 'download='.
  - Observe se a aplicação concatena caminhos fornecidos pelo usuário.
  - Compare arquivo permitido com caminho relativo de teste dentro do lab.
  - Erros que mostram caminhos internos são pistas, não prova definitiva.

IDOR / AUTORIZAÇÃO
  - Compare acesso aos próprios objetos de teste em contas do laboratório.
  - Se alterar um ID permite ler recurso de outra conta de teste sem
    autorização, documente; não acesse dados reais de terceiros.

JWT (JSON WEB TOKEN)
  - Formato: cabecalho.payload.assinatura (3 partes separadas por pontos).
  - Header/payload são Base64URL, NÃO criptografia.
  - Examine 'alg', 'typ', 'sub', 'role', 'exp', 'iat', 'aud'.
  - Decodificar não valida assinatura nem permite editar token legitimamente.

23. WIRESHARK / TSHARK: ROTEIRO DE INVESTIGAÇÃO
======================================================================
ABRIR: File -> Open -> arquivo .pcap/.pcapng.
PASSO A PASSO:
  1) Statistics -> Protocol Hierarchy: quais protocolos predominam?
  2) Statistics -> Conversations: quais IPs conversam mais?
  3) Filtre 'dns' e procure domínios suspeitos.
  4) Filtre 'http' e veja GET/POST, Host, User-Agent, códigos HTTP.
  5) Clique no pacote -> Follow -> TCP Stream (ou HTTP Stream).
  6) Veja 'File -> Export Objects -> HTTP' se houver objetos.
  7) Se houver TLS, payload pode estar cifrado; analise metadados.
  8) Pesquise padrões de flag, credenciais fictícias e nomes de arquivo.

FILTROS DE EXIBIÇÃO (barra do Wireshark)
  ip.addr == <IP>                  origem OU destino
  ip.src == <IP>                   só origem
  ip.dst == <IP>                   só destino
  tcp.port == 80                  porta TCP
  udp.port == 53                  porta UDP
  dns                             DNS
  dns.qry.name contains "ctf"     consulta contendo texto
  http                            HTTP
  http.request.method == "POST"    só POST
  http.response.code == 200       respostas 200
  http.host contains "lab"        host HTTP com texto
  tcp.stream eq 0                 conversa TCP de índice 0
  tcp.analysis.retransmission     retransmissões
  frame contains "flag"           bytes contendo texto
  tls                             TLS
  icmp                            ICMP
  smb2                            SMB2
  ftp                             FTP
  !(arp or mdns)                  exclui ruído comum
Atenção: 'frame contains' encontra bytes; conteúdo TLS cifrado não aparece.

TSHARK (SE INSTALADO)
  tshark -r '<ARQUIVO>' -q -z io,phs
  tshark -r '<ARQUIVO>' -q -z conv,tcp
  tshark -r '<ARQUIVO>' -Y 'dns' -T fields -e dns.qry.name
  tshark -r '<ARQUIVO>' -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
  tshark -r '<ARQUIVO>' -Y 'frame contains "flag"'
  tshark -r '<ARQUIVO>' -q -z follow,tcp,ascii,0
A saída do follow depende de qual stream tem a informação; troque 0.

24. FORENSE: DISCO, MEMÓRIA, LOGS E METADADOS

25. CRIPTOGRAFIA, ENCODING E HASHES
======================================================================
IDENTIFICAÇÃO:
  Base64: letras/números/+/, frequentemente '=' no final; Base64URL usa -_.
  Hex: caracteres 0-9 a-f, geralmente pares de dígitos.
  ROT13/Caesar: substituição de letras, sem segredo criptográfico.
  MD5: 32 hex; SHA1: 40 hex; SHA256: 64 hex (tamanho não é prova).
  XOR: bytes combinados com chave; padrões podem surgir após decodificação.

LINUX:
  printf 'SGVsbG8=' | base64 -d
  printf '48656c6c6f' | xxd -r -p
  printf 'hello' | sha256sum
  echo -n 'hello' | md5sum
  printf 'uryyb' | tr 'A-Za-z' 'N-ZA-Mn-za-m'

PYTHON 3 (WINDOWS OU LINUX)
  python3 -c "import base64;print(base64.b64decode('SGVsbG8=').decode())"
  python3 -c "print(bytes.fromhex('48656c6c6f').decode())"
  python3 -c "import codecs;print(codecs.decode('uryyb','rot_13'))"
  python3 -c "import hashlib;print(hashlib.sha256(b'hello').hexdigest())"
  python3 -c "s='abc';print(''.join(chr(ord(c)^1) for c in s))"
No Windows, se 'python3' falhar, tente 'py -3' ou 'python'.

BASE64URL JWT COM PYTHON:
  python3 -c "import base64,json; t='eyJhbGciOiJub25lIn0.eyJyb2xlIjoidXNlciJ9.'; p=t.split('.')[1];print(json.loads(base64.urlsafe_b64decode(p+'='*(-len(p)%4))))"
O exemplo só DECODIFICA payload de demonstração; não autentica token.

HASH NÃO É CRIPTOGRAFIA REVERSÍVEL. Em desafios de senha/hash, primeiro
identifique algoritmo e formato; use apenas dados fictícios do laboratório.

31. TROUBLESHOOTING: QUANDO NADA FUNCIONA
======================================================================
'command not found' / 'não é reconhecido':
  - Verifique grafia e PATH: which/where/Get-Command.
  - Confira se programa existe. Não dependa de instalação no evento.
'permission denied' / 'acesso negado':
  - Verifique permissões; não tente contornar controles fora do desafio.
'connection refused':
  - Host respondeu, mas porta não aceita; confira IP/porta/serviço.
'connection timed out':
  - Pode ser firewall, rota, serviço indisponível; confira escopo e rede.
'no route to host':
  - Problema de roteamento/conectividade; verifique IP/rota/VPN do lab.
'404':
  - Recurso não encontrado; revise caminho e capitalização.
'403':
  - Acesso proibido; examine autenticação/permissões do desafio.
'500':
  - Erro no servidor; compare requisições e consulte mensagens do lab.
'base64: invalid input':
  - Verifique espaços, padding, Base64URL e se dado é realmente Base64.
'Wireshark não mostra HTTP':
  - Talvez seja HTTPS/TLS, porta diferente ou protocolo encapsulado.
'Nmap mostra filtered':
  - Pode haver firewall; não significa serviço vulnerável.

A. AWK — EXTRAÇÃO DE CAMPOS E ANÁLISE DE LOGS (LINUX)
==========================================================================
O awk lê um arquivo linha a linha e permite selecionar colunas, filtrar
registros, contar ocorrências e somar números. Muito útil quando a flag está
em logs, CSV ou dados textuais. Não é necessário criar script para casos simples.

CONCEITOS:
- $0 = linha inteira; $1 = primeira coluna; $2 = segunda coluna etc.
- NR = número da linha atual; NF = número de campos na linha.
- -F ',' define separador vírgula; -F ':' define dois-pontos.
- {print ...} indica o que mostrar; /erro/ filtra linhas com "erro".
- BEGIN executa antes de ler; END executa após ler o arquivo.
- Em arquivos de texto comuns, o separador padrão é espaço/tab.

1) Mostrar primeira e terceira colunas:
   awk '{print $1, $3}' <ARQUIVO.txt>
   USAR: arquivo em que cada linha tem palavras separadas por espaços.
   RESULTADO: duas colunas; se faltar a terceira, ela aparecerá vazia.

2) Ver números de linha e conteúdo:
   awk '{print NR ": " $0}' <ARQUIVO.txt>
   USAR: localizar em qual linha está uma pista.

3) Extrair segunda coluna de CSV simples:
   awk -F',' '{print $2}' <ARQUIVO.csv>
   ATENÇÃO: CSV com vírgulas dentro de aspas exige parser de CSV; awk simples
   não interpreta esse caso corretamente.

4) Filtrar registros com a palavra ERROR:
   awk '/ERROR/ {print NR, $0}' <ARQUIVO.log>
   USAR: buscar falhas. A busca diferencia maiúsculas de minúsculas.

5) Ignorar cabeçalho e imprimir primeira coluna:
   awk -F',' 'NR>1 {print $1}' <ARQUIVO.csv>

6) Contar quantas vezes cada IP aparece na primeira coluna:
   awk '{contagem[$1]++} END {for (ip in contagem) print contagem[ip], ip}' <ARQUIVO.log> | sort -nr
   USAR: identificar IPs com mais registros. sort -nr coloca maior contagem
   primeiro. Só funciona se o IP estiver na primeira coluna.

7) Contar linhas que contêm 'flag', ignorando caixa:
   awk 'tolower($0) ~ /flag/ {n++; print NR ": " $0} END {print "TOTAL:", n+0}' <ARQUIVO.txt>

8) Somar valores numéricos da terceira coluna:
   awk -F',' 'NR>1 {soma+=$3} END {print soma}' <ARQUIVO.csv>
   USAR: logs tabulares ou estatísticas. Verifique se a coluna é numérica.

9) Procurar HTTP 404 em logs no formato comum (status na nona coluna):
   awk '$9==404 {print $1, $7, $9}' <access.log>
   RESULTADO: IP, recurso e status; somente se o log seguir esse formato.

10) Imprimir últimas 10 linhas de um arquivo:
    tail -n 10 <ARQUIVO>
    Alternativa mais simples do que awk para esse objetivo.

ERROS COMUNS: awk '{print $2}' devolve vazio? Confira as colunas com
awk '{print NF, $0}' <ARQUIVO>. Se separador for ';', use -F';'.

WINDOWS: AWK NÃO É NATIVO DO CMD/POWERSHELL. EQUIVALENTES:
PS> Get-Content '<ARQUIVO.log>' | Select-String 'ERROR'
    Procura linhas que contêm ERROR.
PS> Import-Csv '<ARQUIVO.csv>' | Select-Object -First 5
    Mostra cinco registros; Import-Csv entende cabeçalhos de CSV.
PS> Import-Csv '<ARQUIVO.csv>' -Delimiter ';' | Select-Object -ExpandProperty Nome
    Extrai coluna chamada Nome de CSV separado por ponto e vírgula.
PS> Get-Content '<ARQUIVO.log>' | Group-Object | Sort-Object Count -Descending | Select-Object -First 10
    Mostra as 10 linhas completas mais repetidas (não os IPs isolados).

==========================================================================
B. GREP, SED, CUT, SORT, UNIQ, XARGS — TEXTO (LINUX)
==========================================================================
GREP = encontrar linhas; SED = transformar/selecionar; CUT = recortar colunas;
SORT = ordenar; UNIQ = contar/remover linhas repetidas adjacentes;
XARGS = passar resultados como argumentos a outro comando.

1) Buscar flag sem diferenciar maiúsculas:
   grep -in 'flag' <ARQUIVO.txt>
   -i ignora caixa; -n mostra número da linha.

2) Buscar recursivamente em pasta:
   grep -Rin --exclude='*.bin' 'flag{' <PASTA>
   -R percorre subpastas; --exclude ignora .bin.
   Pode gerar muitos resultados; limite com | head -n 30.

3) Mostrar contexto antes e depois da pista:
   grep -in -C 3 'password' <ARQUIVO.log>
   -C 3 mostra 3 linhas antes e depois.

4) Mostrar linhas 20 a 40:
   sed -n '20,40p' <ARQUIVO.txt>
   -n desativa impressão automática; p imprime intervalo.

5) Trocar palavra só na saída (não altera arquivo):
   sed 's/ERROR/ERRO/g' <ARQUIVO.txt>
   s = substituir; g = todas as ocorrências na linha.
   Evite -i se não quiser modificar o arquivo original.

6) Selecionar primeira e quarta colunas separadas por ':':
   cut -d':' -f1,4 <ARQUIVO.txt>
   -d define separador; -f define campos.

7) Mostrar valores distintos e quantidades:
   sort <ARQUIVO.txt> | uniq -c | sort -nr | head -n 20
   uniq só conta repetições adjacentes; por isso usamos sort antes.

8) Listar nomes de arquivos contendo 'flag' no diretório:
   grep -Rl 'flag' <PASTA>
   -l mostra somente os nomes dos arquivos.

9) Encontrar arquivos .log sem problemas com espaços:
   find <PASTA> -type f -name '*.log' -print0 | xargs -0 grep -in 'error'
   -print0/-0 preservam nomes com espaços; grep procura dentro dos logs.

10) Pesquisar padrões alternativos:
    grep -Ein 'flag|token|secret|password' <ARQUIVO.txt>
    -E habilita alternativas com |.

D. SNORT — IDS E ANÁLISE DE PCAP (LABORATÓRIO)
==========================================================================
Snort é um sistema de detecção de intrusão. Lê tráfego de rede e compara
pacotes com regras. Em CTF, pode ser útil para analisar PCAP e entender alertas.
Há diferenças entre Snort 2 e Snort 3: confira primeiro a versão e a ajuda.

1) Ver versão: snort -V
2) Ver opções: snort -?
3) Ver interfaces: ip -br link
4) Localizar configuração (Linux):
   find /etc -maxdepth 4 -iname '*snort*' 2>/dev/null

SNORT 2 — EXEMPLOS, SE JÁ INSTALADO E CONFIGURADO:
5) Testar configuração:
   sudo snort -T -c /etc/snort/snort.conf
   -T = validar; -c = arquivo de configuração. Se caminho for diferente,
   substitua pelo caminho existente. Se acusar regra ausente, revise includes.

6) Ler captura existente com configuração:
   sudo snort -r <CAPTURA.pcap> -c /etc/snort/snort.conf -A console -q
   -r = ler arquivo; -A console = alertas no terminal; -q = menos mensagens.
   O Snort pode gravar logs dependendo da configuração; use diretório de lab.

7) Regra local SIMPLES de detecção HTTP (Snort 2, sintaxe de demonstração):
   alert tcp any any -> any 80 (msg:"CTF HTTP na porta 80"; sid:1000001; rev:1;)
   alert = gerar alerta; tcp = protocolo; any any = qualquer IP/porta origem;
   -> = direção; any 80 = qualquer destino na porta 80; msg = texto do alerta;
   sid = identificador único da regra; rev = revisão.
   A regra detecta TCP destinado à porta 80, NÃO comprova ataque.
   Salve a linha num arquivo <REGRAS.rules> e referencie-o na configuração
   do laboratório, ou use opção de regras compatível com sua versão.

8) Exemplo de regra com conteúdo em tráfego HTTP sem criptografia:
   alert tcp any any -> any 80 (msg:"CTF palavra teste"; content:"CTF_TESTE"; sid:1000002; rev:1;)
   content busca bytes de texto no payload; não enxerga HTTPS criptografado.

SNORT 3:
- A configuração usa normalmente snort.lua e a estrutura difere do Snort 2.
- Primeiro execute: snort --help
- Para conferir a configuração: snort -c <snort.lua> -T
- Não copie comandos de Snort 2 cegamente para Snort 3.

COMO INTERPRETAR ALERTAS:
- Leia timestamp, regra/sid, IP:porta de origem e destino e protocolo.
- Alerta é INDÍCIO, não prova de comprometimento.
- Confirme no Wireshark/tshark o fluxo relacionado.
- Em PCAP sem pacotes correspondentes, a regra não dispara.

SE SNORT NÃO ESTIVER INSTALADO:
- Para investigar a captura, use Wireshark ou tshark; não precisa instalar
  Snort só para encontrar DNS, HTTP, credenciais de laboratório ou flags.

==========================================================================
E. TCPDUMP E TSHARK — PACOTES DE REDE
==========================================================================
TCPDUMP: captura/exibe pacotes. TSHARK: Wireshark no terminal.
Ambos podem ler PCAP existente sem capturar a rede ao vivo.

1) Interfaces disponíveis:
   tcpdump -D
   tshark -D
2) Ler PCAP sem resolver nomes (mais rápido):
   tcpdump -nn -r <CAPTURA.pcap> | head -n 30
   -nn = não resolver IP/porta para nomes; -r = ler arquivo.
3) Mostrar tráfego HTTP da captura:
   tcpdump -nn -A -r <CAPTURA.pcap> 'tcp port 80'
   -A = mostra conteúdo ASCII. HTTPs/TLS fica criptografado.
4) Filtrar IP e porta na captura:
   tcpdump -nn -r <CAPTURA.pcap> 'host <IP> and port <PORTA>'
5) Mostrar pacotes DNS:
   tshark -r <CAPTURA.pcap> -Y 'dns'
   -Y = filtro de exibição (Wireshark).
6) Extrair domínios consultados:
   tshark -r <CAPTURA.pcap> -Y 'dns.qry.name' -T fields -e dns.qry.name | sort -u
   -T fields = saída em colunas; -e = campo a extrair; sort -u = únicos.
7) Extrair requisições HTTP:
   tshark -r <CAPTURA.pcap> -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
8) Encontrar string no conteúdo de pacotes:
   tshark -r <CAPTURA.pcap> -Y 'frame contains "flag"'
   "contains" busca bytes da string, sem decodificar protocolos ocultos.
9) Estatísticas de conversas TCP:
   tshark -r <CAPTURA.pcap> -q -z conv,tcp
10) Seguir fluxo TCP de índice 0:
    tshark -r <CAPTURA.pcap> -q -z follow,tcp,ascii,0
    Se não for o fluxo desejado, descubra o índice em Wireshark.
11) Capturar somente no lab autorizado, até 100 pacotes:
    sudo tcpdump -i <INTERFACE> -c 100 -w <SAIDA.pcap>
    -i = interface; -c = limite de pacotes; -w = salvar.
    Exige permissões adequadas e autorização de captura.

FILTRO DE CAPTURA x FILTRO DE EXIBIÇÃO:
- tcpdump/BPF: 'host 10.0.0.1 and port 80'
- tshark/Wireshark display: 'ip.addr == 10.0.0.1 && tcp.port == 80'
- Não misture as duas sintaxes.

F. LOGS: FLUXO PRONTO PARA INVESTIGAÇÃO
==========================================================================
CENÁRIO: foi entregue access.log; você precisa identificar picos de erros.
1) file access.log
   Identifica tipo do arquivo.
2) head -n 5 access.log
   Mostra o formato e a posição das colunas.
3) wc -l access.log
   Conta linhas.
4) grep -inE 'flag|token|secret' access.log | head -n 30
   Procura palavras de interesse sem despejar o arquivo todo.
5) awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 15
   Ranking dos IPs da primeira coluna (formato Common/Combined Log).
6) awk '$9 ~ /^4[0-9][0-9]$/ {print $1, $7, $9}' access.log | head
   Mostra respostas HTTP 4xx se o status estiver na nona coluna.
7) grep -inE 'admin|login|\.env|backup' access.log | head -n 30
   Localiza recursos de interesse. Não significa que foram explorados.
8) Se identificar um IP, filtre suas linhas:
   grep -F '<IP>' access.log | head -n 50
   -F trata IP como texto literal (não regex).

WINDOWS POWERSHELL — MESMO OBJETIVO:
PS> Get-Content '.\access.log' -TotalCount 5
PS> (Get-Content '.\access.log' | Measure-Object -Line).Lines
PS> Select-String -Path '.\access.log' -Pattern 'flag','token','secret'
PS> Get-Content '.\access.log' | ForEach-Object { ($_ -split '\s+')[0] } | Group-Object | Sort-Object Count -Descending | Select-Object -First 15
OBS.: ForEach-Object separa por espaços; confirme se o IP é primeiro campo.

==========================================================================
H. COMMAND INJECTION — RECONHECER EM DESAFIOS WEB
==========================================================================
Command injection ocorre quando entrada de usuário é interpretada por shell.
No CTF, procure pistas de comandos do sistema em campos como ping/diagnóstico,
conversores ou utilitários. Teste somente endpoints expressamente autorizados.

DIFERENÇA:
- Linux: separador de comandos em shell pode ser ';' ou '&&'.
- Windows CMD: separador de comandos pode ser '&' ou '&&'.
- O funcionamento depende de filtros, aspas, contexto e interpretador.

EXEMPLOS INOFENSIVOS PARA ENTENDER O SHELL LOCAL:
Linux: printf 'primeiro\n'; printf 'segundo\n'
Windows CMD: echo primeiro & echo segundo
PowerShell: Write-Output 'primeiro'; Write-Output 'segundo'
Cada exemplo mostra dois comandos sequenciais; não prova vulnerabilidade web.

INDÍCIOS EM UM DESAFIO:
- Mensagens de erro com 'sh', 'cmd.exe' ou nomes de utilitários.
- Saída de ping/traceroute aparecendo diretamente na resposta.
- Diferença de resposta conforme caracteres especiais.
- Documentação do desafio dizendo que há execução de comandos.

INTERPRETAÇÃO:
- Se aparecer texto literal, a aplicação pode estar escapando caracteres.
- Se a saída contiver resultado de utilitário, confirme se é comportamento
  previsto pela aplicação antes de concluir que existe injeção.
- Não presuma Linux ou Windows; erros e cabeçalhos podem dar pistas.

J. CHEAT SHEET DE ERROS FREQUENTES
==========================================================================
'command not found': ferramenta ausente ou fora do PATH.
'Permission denied': falta permissão de leitura/execução ou acesso ao recurso.
'No such file or directory': caminho incorreto; confirme pwd, ls e aspas.
'Access is denied' (Windows): permissão insuficiente.
'Connection refused': destino alcançado, mas porta rejeitou conexão.
'Connection timed out': sem resposta no tempo; pode haver filtro/rede indisponível.
'Invalid capture file': PCAP pode estar truncado ou não ser captura válida.
'jq: parse error': conteúdo não é JSON válido ou está incompleto.
'Snort unknown option': verifique snort -V; pode ser Snort 2 vs Snort 3.
'awk empty fields': separador errado ou coluna inexistente.

================== 1. RECEBI ARQUIVO DESCONHECIDO ==================
Linux:
  pwd                                # pasta atual
  ls -lah                            # mostra inclusive arquivos ocultos, tamanhos
  file desafio.bin                   # identifica formato real, não confie na extensão
  stat desafio.bin                   # datas, tamanho e permissões
  sha256sum desafio.bin              # calcula hash para identificar cópias
  strings -a -n 5 desafio.bin | less  # extrai sequências legíveis com >=5 caracteres
  strings -a desafio.bin | grep -Ein 'flag|ctf|pass|token|secret|key' # procura pistas
  xxd -l 128 desafio.bin             # primeiros 128 bytes em hexadecimal
  hexdump -C desafio.bin | head      # alternativa ao xxd
  find . -maxdepth 3 -type f         # lista arquivos até 3 níveis
Windows PowerShell:
  Get-ChildItem -Force               # lista arquivos ocultos
  Get-Item .\desafio.bin | Format-List * # metadados do arquivo
  Get-FileHash .\desafio.bin -Algorithm SHA256 # hash
  Format-Hex -Path .\desafio.bin | Select-Object -First 12 # início hexadecimal
  Get-ChildItem -Recurse -File | Select-String -Pattern 'flag|ctf|secret' # texto em arquivos legíveis
Interpretação: PK no início sugere ZIP; 89 50 4E 47 sugere PNG; 25 50 44 46 sugere PDF; MZ sugere PE Windows; 7F 45 4C 46 sugere ELF.
Próximo passo: use a seção correspondente ao tipo real detectado.

================== 2. FLAG ESCONDIDA EM PASTAS OU TEXTO ==================
Linux:
  find . -type f -iname '*flag*' 2>/dev/null
  find . -type f -name '.*' 2>/dev/null
  grep -RinE 'flag\{|ctf\{|password|secret' . 2>/dev/null
  grep -RIl 'flag' . 2>/dev/null  # mostra apenas nomes de arquivos com ocorrência
  find . -type f -size -10k         # arquivos pequenos, comuns em desafios
Windows PowerShell:
  Get-ChildItem -Force -Recurse -File | Where-Object Name -match 'flag|secret|pass'
  Get-ChildItem -Recurse -File -ErrorAction SilentlyContinue | Select-String -Pattern 'flag\{|ctf\{' -ErrorAction SilentlyContinue
  Get-ChildItem Env:                 # variáveis de ambiente, somente na máquina do desafio
Dica: em Linux, Ctrl+H no gerenciador de arquivos costuma mostrar ocultos; ls -la no terminal.

================== 3. RECEBI PCAP: WIRESHARK ==================
Passos gráficos:
1. File > Open > arquivo.pcapng.
2. Statistics > Protocol Hierarchy: veja HTTP, DNS, SMB, FTP, ICMP etc.
3. Statistics > Conversations: veja quem fala com quem.
4. Filtro 'http' para tráfego HTTP; 'dns' para DNS; 'tcp.stream eq 0' para um fluxo.
5. Clique direito no pacote > Follow > TCP Stream (ou HTTP Stream): veja a conversa completa.
6. File > Export Objects > HTTP (quando houver): arquivos transferidos.
Filtros Wireshark (barra de filtro):
  http
  dns
  dns.qry.name contains "flag"
  http.request
  http.request.method == "POST"
  http.response.code == 200
  http contains "flag"
  tcp contains "flag"
  frame contains "CTF"
  ip.addr == 192.0.2.10
  tcp.port == 80
  smb2
  ftp
  icmp
  tcp.analysis.retransmission
Observações: filtros de exibição não alteram o arquivo. HTTP sem TLS pode revelar texto; HTTPS normalmente é criptografado. 'contains' encontra bytes visíveis, não descriptografa TLS.

================== 4. RECEBI PCAP: TSHARK / TCPDUMP ==================
  tshark -r captura.pcapng -q -z io,phs
    # -r lê arquivo, -q resumo, -z io,phs mostra hierarquia de protocolos
  tshark -r captura.pcapng -Y 'dns' -T fields -e frame.time -e ip.src -e dns.qry.name
    # -Y filtro, -T fields colunas, -e escolhe cada campo
  tshark -r captura.pcapng -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
    # mostra origem, host e caminho solicitado
  tshark -r captura.pcapng -Y 'http.response' -T fields -e http.response.code -e http.content_type
    # mostra códigos HTTP e tipos de conteúdo
  tshark -r captura.pcapng -q -z follow,tcp,ascii,0
    # reconstrói fluxo TCP de índice 0 em texto; teste outros índices
  tcpdump -nn -r captura.pcap 'port 53'
    # -nn não resolve nomes/portas, -r lê PCAP, port 53 filtra DNS
  tcpdump -A -nn -r captura.pcap 'tcp port 80' | less
    # -A exibe payload ASCII; pode conter HTTP em claro
Se comando não existir, use Wireshark gráfico; se campo não existir, confira protocolo com tshark -G fields | grep nome.

================== 5. LOG DE SERVIDOR: AWK / GREP / SORT ==================
Cenário: recebeu access.log e pergunta IP com mais requisições, URL mais acessada, código 404, horário de ataque.
AVISO: os exemplos presumem formato de log HTTP comum, onde $1 é IP, $7 é URL e $9 é status. Confira 'head -n 3 access.log' antes!
  head -n 5 access.log
    # veja estrutura das linhas
  awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -20
    # extrai 1ª coluna (IP), agrupa, conta e mostra os 20 mais frequentes
  awk '{print $7}' access.log | sort | uniq -c | sort -nr | head -20
    # URLs mais requisitadas no formato padrão
  awk '$9==404 {print $1, $7}' access.log | head -30
    # IP e URL em respostas 404 (varredura ou caminhos inexistentes)
  awk '$9==500 {print $1, $7}' access.log | head -30
    # erros 500, que podem indicar falhas de aplicação
  grep -Ein 'admin|login|\.env|\.git|wp-login|flag|backup' access.log | head -50
    # encontra caminhos/palavras interessantes, com número da linha
  grep ' 404 ' access.log | wc -l
    # conta linhas com texto 404 (menos preciso que awk $9)
  awk '{print $1}' access.log | sort -u | wc -l
    # número de IPs únicos
  awk '{print $4}' access.log | sort | uniq -c | sort -nr | head
    # conta timestamps aproximados; confirme formato
  awk -F '"' '{print $2}' access.log | head
    # -F define aspas como separador, extrai trecho da requisição
Exemplo: linha '192.0.2.10 - - [date] "GET /admin HTTP/1.1" 404 123' => $1 IP, $7 /admin, $9 404.

================== 6. LOG DE REDE / ALERTA SNORT ==================
Snort é IDS/IPS: inspeciona tráfego e dispara alertas conforme regras. Não presume que alerta = comprometimento.
Descoberta: snort -V (versão); snort -? (ajuda). Sintaxe varia entre Snort 2 e Snort 3.
Regra didática Snort 2 (em arquivo local.rules de LABORATÓRIO):
  alert tcp any any -> any 80 (msg:"LAB HTTP para porta 80"; sid:1000001; rev:1;)
  # alert=gera alerta; tcp=protocolo; any any=origem IP/porta;
  # ->=sentido; any 80=destino porta 80; msg=texto; sid=ID único; rev=versão.
Regra didática para conteúdo em HTTP não criptografado:
  alert tcp any any -> any 80 (msg:"LAB texto flag em HTTP"; content:"flag{"; nocase; sid:1000002; rev:1;)
  # content procura bytes 'flag{'; nocase ignora maiúsculas; não funciona para HTTPS criptografado.
Com Snort 2 configurado no laboratório:
  snort -T -c /etc/snort/snort.conf
    # valida a configuração antes de executar
  snort -r captura.pcap -c /etc/snort/snort.conf -A console
    # lê PCAP e exibe alertas no console, se a instalação aceitar essas opções
Snort 3 usa snort.lua e regras/flags diferentes: verifique 'snort --help' e os arquivos locais de configuração.
Se não houver Snort, abra PCAP no Wireshark/tshark e filtre por IP/porta/conteúdo do alerta.

================== 7. WEB: PRIMEIRA INSPEÇÃO SEM EXPLORAR ==================
No navegador:
1. Abra a URL do desafio. Observe título, mensagens, parâmetros ?id=, formulários e redirecionamentos.
2. Ctrl+U para código-fonte HTML; Ctrl+Shift+I para DevTools (se permitido).
3. Aba Network: veja requisições e respostas, status 200/301/403/404/500, cookies, JSON.
4. Aba Sources: veja JS local; pesquise por 'flag', 'token', 'api', 'debug', 'TODO'.
5. Verifique caminhos apenas se incluídos no escopo do desafio.
Comandos para URL de laboratório:
  curl -I http://<HOST>:<PORTA>/
    # cabeçalhos HTTP, sem corpo
  curl -i http://<HOST>:<PORTA>/
    # -i inclui cabeçalhos e corpo
  curl -s http://<HOST>:<PORTA>/ | grep -Ein 'flag|TODO|secret|api'
    # -s silencioso; procura pistas no HTML retornado
  curl -i 'http://<HOST>:<PORTA>/robots.txt'
    # robots.txt pode mencionar caminhos; não prova permissão para acessá-los
  curl -i 'http://<HOST>:<PORTA>/.well-known/security.txt'
    # arquivo de política, quando presente
  curl -i -X OPTIONS 'http://<HOST>:<PORTA>/'
    # consulta métodos anunciados; não garante que funcionem
Códigos: 200 OK; 301/302 redirecionamento; 400 requisição inválida; 401 não autenticado; 403 negado; 404 não encontrado; 500 erro interno.

================== 8. WEB: INPUT, INJECTION E DIAGNÓSTICO EM LAB ==================
Cenário: formulário aceita entrada e desafio pergunta se é refletida, validada ou executada.
1. Envie uma palavra inofensiva única, como TESTE_CTF_123, e observe se retorna na página/resposta.
2. Confira se o valor aparece em HTML, atributo, JS, URL ou apenas no servidor.
3. Para suspeita de command injection, compare respostas a entradas comuns e registre diferenças de tempo/erro no ambiente autorizado. Não presuma execução por uma mensagem de erro.
4. Verifique se o backend do LAB usa shell Linux ou Windows, pois sintaxe e ferramentas diferem.
5. Prefira comprovações não destrutivas fornecidas pelo próprio desafio. Não execute comandos para apagar dados, exfiltrar credenciais ou obter persistência.
Comandos de inspeção de entrada via curl:
  curl -i --get --data-urlencode 'q=TESTE_CTF_123' 'http://<HOST>:<PORTA>/search'
    # --get coloca q na query; --data-urlencode faz escaping seguro
  curl -i -X POST --data-urlencode 'q=TESTE_CTF_123' 'http://<HOST>:<PORTA>/search'
    # envia formulário POST URL-encoded
  curl -i -H 'Content-Type: application/json' -d '{"q":"TESTE_CTF_123"}' 'http://<HOST>:<PORTA>/api/search'
    # envia JSON; só use se a API espera JSON
Sinais úteis: reflexão direta, erro de parser, mudança de status, mensagens de validação, resposta diferente entre entradas equivalentes.

================== 9. NMAP: RECEBI IP DE MÁQUINA DE LAB ==================
  nmap -sT -sV -p 21,22,80,443,445 <IP>
    # -sT conexão TCP; -sV tenta identificar serviço/versão; -p portas selecionadas
  nmap -sT -p- <IP>
    # -p- examina todas as portas TCP; pode demorar, só se autorizado
  nmap -sT -sV -p 80,443 --script http-title <IP>
    # script informativo para título HTTP
  nmap -sT -sV -p 445 --script smb-os-discovery <IP>
    # consulta informações SMB em laboratório, quando disponíveis
Leitura: OPEN = serviço responde; CLOSED = porta acessível sem serviço; FILTERED = filtrada/sem resposta conclusiva.
Mapa rápido: 21 FTP, 22 SSH, 53 DNS, 80/443 web, 139/445 SMB, 3389 RDP, 3306 MySQL, 5432 PostgreSQL.
Se Nmap não instalado: Linux 'nc -vz <IP> 80' (se nc existir); Windows PowerShell 'Test-NetConnection <IP> -Port 80'.

  ls -lah /home              # diretórios de usuários
  find /home -type f -iname '*flag*' 2>/dev/null # apenas se diretório estiver no escopo
  journalctl -n 30 --no-pager # últimas mensagens do journal, se permitido
  tail -n 50 /var/log/auth.log # autenticação em distros com auth.log; pode exigir acesso
  history | tail -30         # comandos da sessão, se histórico existir
Para logs: 'grep -Ein "failed|error|denied" <LOG> | tail -30'.

================== 13. FORENSE DE IMAGEM / ESTEGANOGRAFIA ==================
  file imagem.png                  # identifica formato real
  exiftool imagem.jpg             # metadados EXIF, se ferramenta disponível
  strings -a imagem.png | grep -Ei 'flag|ctf|secret'
  binwalk imagem.png              # identifica assinaturas de dados embutidos
  unzip -l suspeito.zip           # lista conteúdo sem extrair
  7z l suspeito.zip               # alternativa, se instalado
  python3 -c 'from PIL import Image; im=Image.open("imagem.png"); print(im.size, im.mode)' # se Pillow instalado
Para PNG: veja metadados, canais de cor, dimensões, chunks, bytes após IEND. Para JPEG: EXIF e arquivos anexados. Para ZIP: listagem e nomes antes de extrair.
Não execute binários extraídos sem ambiente isolado e autorização.

================== 14. CRIPTO / ENCODING: IDENTIFICAR ANTES DE DECODIFICAR ==================
Base64: costuma usar A-Z a-z 0-9 + / e padding =; nem toda string assim é Base64.
  echo 'ZmxhZ3t0ZXN0ZX0=' | base64 -d
    # retorna flag{teste}; é codificação, não criptografia
Hex:
  echo '666c61677b74657374657d' | xxd -r -p
    # -r -p converte hex puro em bytes => flag{teste}
ROT13:
  echo 'synt{grfgr}' | tr 'A-Za-z' 'N-ZA-Mn-za-m'
    # substituição ROT13 => flag{teste}
URL decode Python:
  python3 -c 'import urllib.parse; print(urllib.parse.unquote("flag%7Bteste%7D"))'
Hashes:
  printf '%s' 'teste' | sha256sum
    # printf sem quebra de linha; hash NÃO é reversível diretamente
  md5sum arquivo.txt; sha256sum arquivo.txt
    # identifica integridade; não confundir hash com texto codificado
Dica: texto aparentemente aleatório pode ser compactado, cifrado ou binário; não tente 'base64 -d' cegamente em tudo.

================== 15. JSON / CSV / JQ / SED ==================
  jq '.' resposta.json
    # formata JSON
  jq -r '.users[] | [.name,.role] | @tsv' resposta.json
    # extrai nome e papel de array users; ajuste chaves ao JSON real
  jq -r '.. | strings | select(test("flag|ctf";"i"))' resposta.json
    # busca strings contendo flag/ctf em profundidade
  sed -n '1,30p' arquivo.txt
    # mostra linhas 1–30 sem alterar arquivo
  sed -n '/ERROR/p' app.log
    # mostra linhas que contêm ERROR
  cut -d ',' -f 1,3 dados.csv | head
    # extrai colunas 1 e 3 de CSV simples (não trata vírgulas dentro de aspas)
  awk -F, 'NR>1 {print $1,$3}' dados.csv | head
    # separador vírgula; pula cabeçalho; também não trata CSV complexo

================== 16. WINDOWS AD / EVENTOS (LAB) ==================
Cenário: desafio entrega logs Windows e pede usuário, máquina, horário ou falha de autenticação.
IDs úteis: 4624 logon sucesso; 4625 falha; 4688 processo criado (se auditoria ativada); 4720 usuário criado; 4740 conta bloqueada; 4768 solicitação TGT; 4769 solicitação ticket de serviço; 4771 pré-autenticação Kerberos falhou.
PowerShell:
  Get-WinEvent -FilterHashtable @{LogName='Security';Id=4769} -MaxEvents 20 | Format-List TimeCreated,Id,Message
    # tickets de serviço; eventos dependem de auditoria e privilégios
  Get-WinEvent -FilterHashtable @{LogName='Security';Id=4740} -MaxEvents 20 | Format-List TimeCreated,Message
    # contas bloqueadas
  Get-ADDomain
    # informações do domínio somente com módulo AD e permissões
  Get-ADUser -Filter * | Select-Object -First 20 SamAccountName,Enabled
    # enumeração de usuários somente no domínio de laboratório autorizado
Se comandos Get-AD* não existirem: módulo RSAT pode não estar instalado; não é erro do desafio necessariamente.

================== 17. BINÁRIO / REVERSING: TRIAGEM SEGURA ==================
  file programa
  sha256sum programa
  strings -a -n 6 programa | grep -Ein 'flag|wrong|correct|password|usage'
  readelf -h programa           # ELF: cabeçalho
  readelf -s programa | head    # ELF: símbolos
  objdump -d programa | head -60 # desmontagem inicial, sem executar
Windows PE: 'file programa.exe', 'strings', 'Format-Hex', ferramenta de análise estática disponível.
Observe mensagens de erro, strings codificadas, funções de comparação e argumentos esperados. Só execute amostras em VM de desafio, não no computador institucional.

================== 18. MINI-CENÁRIOS RESOLVIDOS ==================
A) Pergunta: 'Qual IP fez mais requisições?'
   Material: access.log. Solução: head -n 2 access.log; awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
   Leia a primeira linha da saída: contagem + IP. Valide se $1 é IP.
B) Pergunta: 'Qual domínio suspeito foi consultado?'
   Material: captura.pcapng. Solução: tshark -r captura.pcapng -Y dns.qry.name -T fields -e dns.qry.name | sort | uniq -c | sort -nr
   Compare frequência e nomes estranhos; suspeito não significa automaticamente malicioso.
C) Pergunta: 'Qual arquivo foi baixado por HTTP?'
   Wireshark: File > Export Objects > HTTP; ou filtre 'http.response' e Follow Stream.
   Observe Content-Disposition, URI e corpo; não execute arquivos extraídos.
D) Pergunta: 'Qual conta teve falhas de login?'
   Windows LAB: Get-WinEvent -FilterHashtable @{LogName='Security';Id=4625} -MaxEvents 30 | Format-List TimeCreated,Message
   Identifique TargetUserName no texto do evento.
E) Pergunta: 'Há texto escondido na imagem?'
   file, exiftool, strings, binwalk; depois inspeção visual e canais, se ferramentas existirem.
F) Pergunta: 'Qual serviço roda na porta 8080?'
   nmap -sT -sV -p 8080 <IP> ; curl -I http://<IP>:8080/
   Compare banner, título e resposta; versão detectada pode estar errada.
G) Pergunta: 'A flag parece ZmxhZ3...'
   echo '<TEXTO>' | base64 -d; confira se resultado legível e formato correto.
H) Pergunta: 'Qual endpoint retorna erro 500?'
   awk '$9==500 {print $7}' access.log | sort | uniq -c | sort -nr
   Confirme formato do log; veja IP, horário e caminho associado.
I) Pergunta: 'Há processo incomum no Windows?'
   Get-Process | Sort-Object CPU -Descending | Select-Object -First 20 Name,Id,CPU
   Compare com enunciado; alto uso não prova malware.
J) Pergunta: 'Encontrar mensagem em tráfego HTTP'
   Wireshark: filtro http; selecione requisição relevante; Follow > TCP Stream; pesquise flag, token, comentário ou conteúdo retornado.

================== 19. ARMADILHAS QUE FAZEM PERDER TEMPO ==================
- Trocar filtros de captura por filtros de exibição: Wireshark 'http' é filtro de exibição.
- Rodar 'grep' em binário e concluir que não há nada: tente 'strings' e 'file'.
- Achar que HTTPS em PCAP é legível sem chaves: normalmente não é.
- Usar 'awk $9' sem conferir formato do access.log.
- Copiar '<IP>' literalmente: substitua pelos dados do laboratório.
- Rodar comando Linux no CMD: verifique shell e sistema.
- Interpretar 403 como ausência de recurso: 403 = acesso negado.
- Confundir MD5/SHA256 com Base64: hash não é decodificação.
- Tratar saída de scanner como prova de exploração.
- Perder 30 minutos em um único desafio quando há pontos mais fáceis.

---------------------------------------------------------
1. COMO PENSAR DURANTE O CTF
---------------------------------------------------------

Quando receber um desafio:

1) Leia o texto inteiro e destaque palavras importantes.
2) Identifique o tipo: rede/PCAP, web, criptografia, forense, imagem, malware,
   Linux, Windows, engenharia reversa ou combinação.
3) Veja quais arquivos e informações foram fornecidos.
4) Faça uma hipótese simples e teste uma coisa por vez.
5) Anote comando, resultado e próxima hipótese.
6) Se não funcionar, não repita igual: mude a abordagem.
7) Procure a flag e valide o formato pedido.

Exemplo de anotação:
Desafio: captura de rede
Pista: “conversa suspeita”
Hipótese: há comunicação HTTP ou DNS
Ação: abrir PCAP no Wireshark; olhar Protocol Hierarchy; filtrar http/dns
Resultado: IP e domínio encontrados
Próximo passo: seguir fluxo TCP e verificar conteúdo

---------------------------------------------------------
2. LINUX E TERMINAL — EXPLICAÇÃO DOS COMANDOS
---------------------------------------------------------

O terminal permite navegar, localizar arquivos, ler conteúdo e executar ferramentas.

NAVEGAR
--------
pwd
Mostra o diretório em que você está.
Use quando não souber onde está trabalhando.

ls
Lista arquivos e pastas.

ls -la
Lista também arquivos ocultos (nomes que começam com ponto), permissões,
proprietário e tamanho. Muito útil porque pistas podem estar em .arquivo.

cd pasta
Entra na pasta.

cd ..
Volta um nível.

mkdir analise
Cria uma pasta para organizar o trabalho.

cp arquivo arquivo.bak
Copia um arquivo. Use cópias para preservar o original.

IDENTIFICAR E LER
-----------------
file arquivo
Identifica o tipo real do arquivo, mesmo se a extensão estiver errada.
Exemplo: algo.jpg pode ser, na verdade, um ZIP ou arquivo de texto.

cat arquivo.txt
Mostra o conteúdo inteiro. Melhor para arquivos pequenos.

less arquivo.txt
Abre leitura paginada. Use setas/PageUp/PageDown e pressione q para sair.

head -n 20 arquivo.txt
Mostra as primeiras 20 linhas.

tail -n 20 arquivo.txt
Mostra as últimas 20 linhas.

wc -l arquivo.txt
Conta linhas. Também pode ajudar a medir arquivos.

PESQUISAR
----------
grep -ni "flag" arquivo.txt
Procura “flag” ignorando maiúsculas/minúsculas e mostra números das linhas.

grep -RniE 'flag|password|token|secret' .
Procura palavras comuns em arquivos da pasta atual e subpastas.
-R = recursivo; -n = linha; -i = ignora maiúsculas/minúsculas.
Pode retornar muita coisa; filtre por diretório ou extensão se necessário.

find . -type f
Lista arquivos, inclusive em subpastas.

find . -type f -name "*.txt"
Procura apenas arquivos TXT.

find . -type f -size +1M
Procura arquivos maiores que 1 MB.

strings arquivo.bin
Mostra trechos de texto legíveis encontrados em um arquivo binário.
Use quando o arquivo não abre como texto, mas pode conter mensagens, URLs ou flags.

xxd arquivo | head
Mostra bytes em hexadecimal e uma coluna de texto aproximada.
Use para identificar cabeçalhos ou conteúdo codificado.

ARQUIVOS COMPACTADOS
---------------------
unzip -l arquivo.zip
Lista o que existe no ZIP sem extrair.

unzip arquivo.zip
Extrai o conteúdo.

tar -tf arquivo.tar
Lista arquivos dentro de TAR.

tar -xvf arquivo.tar
Extrai TAR.

7z l arquivo.7z
Lista conteúdo 7z.

7z x arquivo.7z
Extrai 7z, se o programa estiver instalado.

DICA: Se a extração pedir senha, procure pistas no enunciado, nome do arquivo,
outros artefatos e metadados. Não tente adivinhar aleatoriamente sem estratégia.

---------------------------------------------------------
3. WIRESHARK — GUIA PASSO A PASSO
---------------------------------------------------------

O Wireshark analisa capturas de rede (PCAP/PCAPNG). Ele mostra os pacotes
e permite filtrar protocolos, IPs, portas e conteúdo.

ABRIR A CAPTURA
----------------
1) Abra o Wireshark.
2) File > Open.
3) Selecione o arquivo .pcap ou .pcapng.
4) Aguarde carregar.
5) Observe os protocolos e endereços na lista.

AS TRÊS ÁREAS
---------------
Packet List:
Lista de pacotes. Cada linha é uma comunicação capturada.

Packet Details:
Ao selecionar pacote, mostra camadas, por exemplo:
Ethernet > IP > TCP > HTTP.

Packet Bytes:
Mostra os bytes em hexadecimal e texto ASCII quando legível.

COMO LER UM PACOTE
-------------------
Clique em um pacote.
Expanda as setas das camadas:
- Ethernet: endereços MAC
- Internet Protocol (IP): IP de origem e destino
- TCP/UDP: portas
- DNS/HTTP: dados do protocolo

Perguntas úteis:
- Quem iniciou a comunicação?
- Qual IP aparece repetidamente?
- Qual serviço/porta está sendo usado?
- Existe nome de domínio?
- Há dados de texto, arquivo ou credencial de laboratório?

FILTROS DE EXIBIÇÃO
--------------------
Digite na barra de filtro e pressione Enter.
Eles só escondem/mostram pacotes; não apagam a captura.

dns
Mostra tráfego DNS. Use para descobrir domínios consultados.

http
Mostra HTTP sem criptografia. Pode revelar requisições e respostas.

tls
Mostra tráfego TLS. O conteúdo costuma estar criptografado, mas metadados podem
ajudar, como IPs, certificados e nomes disponíveis na captura.

tcp
Mostra TCP.

udp
Mostra UDP.

icmp
Mostra ICMP, frequentemente usado por ping.

arp
Mostra resolução de endereços na rede local.

ip.addr == 192.168.1.10
Mostra pacotes em que o IP aparece como origem OU destino.

ip.src == 192.168.1.10
Mostra somente pacotes originados nesse IP.

ip.dst == 192.168.1.10
Mostra somente pacotes destinados a esse IP.

tcp.port == 80
Mostra TCP com porta 80.

udp.port == 53
Mostra UDP com porta 53, comum para DNS.

http.request
Mostra requisições HTTP.

dns.qry.name
Filtro para campo de nome consultado em DNS; use junto de dns, por exemplo:
dns && dns.qry.name

tcp.flags.syn == 1
Mostra pacotes com flag SYN. Pode ajudar a observar tentativas de conexão.

frame contains "flag"
Procura bytes/texto “flag” no pacote, quando o conteúdo está visível.

tcp contains "password"
Procura texto password dentro de segmentos TCP; pode não funcionar se o conteúdo
estiver criptografado ou dividido em segmentos.

Combinar:
ip.addr == 192.168.1.10 && tcp
Mostra TCP envolvendo aquele IP.

dns || http
Mostra DNS ou HTTP.

!(arp or icmp)
Esconde ARP e ICMP.

OBSERVAÇÃO: IPs acima são exemplos. Troque pelos endereços vistos no desafio.

FOLLOW TCP STREAM — MUITO IMPORTANTE
-------------------------------------
1) Selecione um pacote TCP.
2) Clique com o botão direito.
3) Follow > TCP Stream.
4) O Wireshark reúne os dados daquele fluxo em uma conversa.
5) Observe texto enviado e recebido.
6) Use o seletor de fluxo para navegar em outras conversas.
7) Feche a janela e continue investigando.

Por que isso ajuda?
Pacotes separados podem parecer incompreensíveis. O Follow Stream organiza a
conversa e pode revelar:
- URLs e parâmetros
- Mensagens HTTP
- Dados enviados pelo cliente
- Respostas do servidor
- Texto que contenha uma pista ou flag

Se aparecer conteúdo ilegível, pode estar comprimido, codificado ou criptografado.
Não conclua que não há informação: examine outros fluxos e protocolos.

ESTATÍSTICAS
-------------
Statistics > Protocol Hierarchy
Mostra quais protocolos aparecem e a quantidade. Bom para começar a captura.

Statistics > Conversations
Mostra pares de IPs/portas e volume de dados. Ajuda a descobrir quem conversou
com quem e quais fluxos parecem relevantes.

Statistics > Endpoints
Lista hosts vistos. Ajuda a identificar IPs internos/externos.

Statistics > DNS
Pode resumir consultas DNS, dependendo da versão e captura.

EXPORTAR ARQUIVOS
-----------------
File > Export Objects > HTTP
Se houver objetos HTTP recuperáveis, permite salvar arquivos transferidos.
Depois use file, strings, exiftool ou outras ferramentas para analisar.

FILTRO DE CAPTURA X FILTRO DE EXIBIÇÃO
----------------------------------------
Filtro de exibição:
- Usado depois que os pacotes já foram capturados.
- Exemplo: http
- Sintaxe: ip.addr == 10.0.0.5

Filtro de captura:
- Usado antes/durante a captura para limitar o que será registrado.
- Exemplos: host 10.0.0.5, port 53, tcp, udp
- Sintaxe diferente da barra de display filters.

---------------------------------------------------------
4. TSHARK — WIRESHARK NO TERMINAL
---------------------------------------------------------

tshark -r captura.pcap
Lê a captura pelo terminal.

tshark -r captura.pcap -Y dns
Exibe apenas pacotes que combinam com o filtro DNS.

tshark -r captura.pcap -Y http
Exibe HTTP.

tshark -r captura.pcap -Y "ip.addr == 10.0.0.5"
Filtra por IP.

tshark -r captura.pcap -c 20
Limita a saída a 20 pacotes.

tshark -r captura.pcap -T fields -e ip.src -e ip.dst -e dns.qry.name
Mostra campos escolhidos: IP de origem, destino e nome DNS.
Se algum campo não existir no pacote, ficará vazio.

-Y é filtro de exibição.
-r indica arquivo de captura.
-c limita número de pacotes.
-T fields escolhe formato de campos.

---------------------------------------------------------
5. REDE E NMAP — ENUMERAÇÃO
---------------------------------------------------------

Enumeração significa descobrir quais hosts/serviços existem no ambiente.
No CTF, use somente o IP ou rede autorizada.

ip a
Mostra interfaces de rede e endereços IP locais.

ip route
Mostra rotas e gateway.

ping -c 4 IP
Envia quatro solicitações ICMP para testar conectividade. Alguns hosts bloqueiam
ping, então ausência de resposta não prova que o host está desligado.

nslookup dominio
Consulta DNS.

dig dominio
Consulta DNS com mais detalhes.

curl -I http://ALVO
Faz requisição HTTP HEAD e mostra cabeçalhos.

curl -i http://ALVO
Mostra cabeçalhos e corpo da resposta.

NMAP
----
nmap -sV -sC IP
Verifica serviços e versões e executa scripts padrão no alvo autorizado.
-sV tenta identificar versões.
-sC usa scripts padrão.

nmap -p 22,80,443 IP
Verifica somente portas escolhidas.

nmap -p- IP
Verifica todas as portas TCP. Pode levar tempo e gerar tráfego; use apenas se
o escopo permitir.

nmap -oN resultado.txt IP
Salva resultado em texto normal.

COMO INTERPRETAR
----------------
Porta 22: frequentemente SSH.
Porta 80: frequentemente HTTP.
Porta 443: frequentemente HTTPS.
Porta 21: frequentemente FTP.
Porta 25: frequentemente SMTP.
Porta 53: DNS.
Porta 3306: frequentemente MySQL.
Porta 5432: frequentemente PostgreSQL.
Porta 3389: frequentemente RDP.
Porta 8080: HTTP alternativo/painel.

Porta aberta não significa vulnerabilidade automaticamente.
Identifique serviço, versão, banner e pistas do desafio antes de concluir.

---------------------------------------------------------
6. WEB — INVESTIGAÇÃO DE SITE
---------------------------------------------------------

Se o desafio fornece URL:

1) Abra no navegador.
2) Leia o conteúdo e o enunciado.
3) Clique com F12 para abrir DevTools.
4) Veja Elements/Inspector, Network, Console e Application/Storage.
5) Observe requisições, parâmetros, cookies, redirecionamentos e respostas.
6) Não envie dados reais; teste apenas no site do desafio.

VIEW SOURCE / INSPECT
---------------------
Procure:
- Comentários HTML
- Caminhos de arquivos JS
- Campos escondidos
- Nomes de endpoints
- Mensagens de erro
- Referências a APIs

Network:
- Recarregue a página com DevTools aberto.
- Clique em uma requisição.
- Observe URL, método, headers, payload e resposta.
- Filtre Fetch/XHR para chamadas de API.

robots.txt
----------
Tente abrir /robots.txt no domínio do desafio.
Pode indicar caminhos que buscadores devem evitar; em CTF, às vezes há pistas.
Não significa que os caminhos sejam secretos ou protegidos.

curl
----
curl -I URL
Cabeçalhos apenas.

curl -i URL
Cabeçalhos + corpo.

curl -L URL
Segue redirecionamentos.

curl -s URL
Saída silenciosa, útil para encadear com less/grep.

Exemplo:
curl -s http://alvo | grep -i flag
Use URL real do desafio.

HTTP
----
GET: normalmente busca conteúdo.
POST: normalmente envia dados.
Cookie: pode manter sessão.
Header: metadados da requisição/resposta.
Status 200: sucesso comum.
Status 301/302: redirecionamento.
Status 401: autenticação requerida.
Status 403: acesso proibido.
Status 404: não encontrado.
Status 500: erro interno.

SQL / BANCO
------------
Se houver tela de login ou busca:
- Observe mensagens de erro.
- Veja se entradas são tratadas de modo diferente.
- Identifique tecnologia e parâmetros.
- Não apague nem altere dados.
- Teste apenas no laboratório e de forma não destrutiva.

XSS
----
Cross-site scripting envolve conteúdo interpretado como script no navegador.
No CTF, examine como a entrada aparece na página:
- texto comum?
- atributo HTML?
- código JavaScript?
- resposta refletida?
Não teste em sites reais nem em usuários terceiros.

---------------------------------------------------------
7. BASE64, HEX, ROT13, HASH E JWT
---------------------------------------------------------

BASE64
------
Base64 é codificação, não criptografia. Pode ser revertida sem chave.

echo 'SGVsbG8=' | base64 -d
Resultado: Hello

echo 'Hello' | base64
Codifica texto para Base64.

Pistas:
- Letras, números, +, / e às vezes = no final.
- Pode aparecer em arquivos, URLs, tokens e capturas.
- Se decodificar e sair texto estranho, veja se há outra camada.

HEX
---
xxd arquivo
Mostra bytes em hexadecimal.

echo '48656c6c6f' | xxd -r -p
Converte hex em bytes; exemplo resulta em Hello.

ROT13
-----
tr 'A-Za-z' 'N-ZA-Mn-za-m'
Aplica ROT13 a texto digitado via pipe.
ROT13 troca cada letra pela que está 13 posições à frente.
Aplicar novamente reverte.

HASH
----
sha256sum arquivo
Calcula SHA-256.

md5sum arquivo
Calcula MD5.

Hash é uma impressão digital; não é decodificado como Base64.
Se o desafio fornece hash de senha, procure pista sobre algoritmo e formato.
Use ferramentas de cracking somente com hash fornecido no CTF e dentro das regras.

JWT
---
Um JWT costuma ter três partes separadas por ponto:
header.payload.signature

Header e payload podem ser Base64URL.
Decodificar payload permite ler claims, mas não valida assinatura nem autoriza acesso.
Nunca coloque tokens pessoais em sites públicos de decodificação.

14. COMANDOS PRONTOS — LINUX (COPIAR, ALTERAR E EXECUTAR)
=========================================================

Como usar esta seção:
- Copie o comando.
- Troque somente o que estiver entre <...> pelos dados do desafio.
- Remova os sinais < > ao substituir.
- Se um caminho tiver espaços, coloque-o entre aspas.
- Antes de executar, confira se está na pasta correta com pwd e ls.
- Alguns comandos podem não estar instalados no ambiente. Se aparecer
  “command not found”, pule para outra ferramenta disponível.

DICA: para facilitar, defina variáveis no terminal. Depois você troca o valor
uma vez e reutiliza nos comandos.

A) DEFINIR CAMINHOS E NOMES
-----------------------------
ARQUIVO="/caminho/para/arquivo.pcap"
PASTA="/caminho/para/pasta"
ALVO="10.10.10.10"
URL="http://10.10.10.10"

Exemplo realista de caminho:
ARQUIVO="$HOME/Downloads/captura.pcap"

Verifique:
echo "$ARQUIVO"
ls -lh "$ARQUIVO"
file "$ARQUIVO"

IMPORTANTE: essas variáveis valem apenas no terminal atual. Se abrir outro terminal,
defina-as novamente.

B) IDENTIFICAR QUALQUER ARQUIVO
-------------------------------
file "<CAMINHO_DO_ARQUIVO>"
Exemplo:
file "$HOME/Downloads/desafio.bin"

Ver tamanho:
ls -lh "<CAMINHO_DO_ARQUIVO>"

Ver metadados básicos:
stat "<CAMINHO_DO_ARQUIVO>"

Calcular SHA-256:
sha256sum "<CAMINHO_DO_ARQUIVO>"

C) PROCURAR FLAGS E PALAVRAS EM UMA PASTA
-------------------------------------------
grep -RniE 'FLAG\{|FIAP\{|flag|password|token|secret' "<PASTA_DO_DESAFIO>" 2>/dev/null

Exemplo:
grep -RniE 'FLAG\{|FIAP\{|flag|password|token|secret' "$HOME/Downloads/ctf" 2>/dev/null

Procurar somente arquivos TXT:
find "<PASTA_DO_DESAFIO>" -type f -name "*.txt"

Procurar arquivos ocultos:
find "<PASTA_DO_DESAFIO>" -type f -name ".*"

D) EXTRAIR STRINGS DE ARQUIVO SUSPEITO
---------------------------------------
strings -n 5 "<ARQUIVO>" | less

Salvar strings em outro arquivo:
strings -n 5 "<ARQUIVO>" > strings.txt

Procurar flag nas strings:
strings -n 5 "<ARQUIVO>" | grep -iE 'FLAG\{|FIAP\{|flag'

E) HEXADECIMAL
--------------
Mostrar bytes:
xxd "<ARQUIVO>" | head -n 40

Converter texto hexadecimal para arquivo:
xxd -r -p "<ARQUIVO_HEX>" > resultado.bin

Se o hex estiver escrito em uma linha de texto:
echo '<HEX_AQUI>' | xxd -r -p

F) BASE64
----------
Decodificar arquivo Base64:
base64 -d "<ARQUIVO_BASE64>" > decodificado.bin

Decodificar texto Base64:
echo '<BASE64_AQUI>' | base64 -d

Codificar texto:
echo -n '<TEXTO_AQUI>' | base64

Se a saída parecer outro formato, rode:
file decodificado.bin
strings decodificado.bin | head

G) ZIP / TAR
-------------
Listar ZIP:
unzip -l "<ARQUIVO.zip>"

Extrair ZIP para pasta:
mkdir -p "<PASTA_DESTINO>"
unzip "<ARQUIVO.zip>" -d "<PASTA_DESTINO>"

Listar TAR:
tar -tf "<ARQUIVO.tar>"

Extrair TAR:
mkdir -p "<PASTA_DESTINO>"
tar -xf "<ARQUIVO.tar>" -C "<PASTA_DESTINO>"

H) WIRESHARK / PCAP
-------------------
Abrir PCAP no Wireshark:
wireshark "<ARQUIVO.pcap>"

Ver DNS no terminal:
tshark -r "<ARQUIVO.pcap>" -Y dns

Ver HTTP:
tshark -r "<ARQUIVO.pcap>" -Y http

Ver tráfego de um IP:
tshark -r "<ARQUIVO.pcap>" -Y "ip.addr == <IP>"

Exemplo:
tshark -r "$HOME/Downloads/captura.pcap" -Y "ip.addr == 10.10.10.10"

Mostrar origem, destino e DNS:
tshark -r "<ARQUIVO.pcap>" -T fields -e ip.src -e ip.dst -e dns.qry.name

Mostrar pacotes com texto flag:
tshark -r "<ARQUIVO.pcap>" -Y 'frame contains "flag"'

Exportar lista de conversas TCP:
tshark -r "<ARQUIVO.pcap>" -q -z conv,tcp

I) NMAP — ALVO DO CTF
----------------------
Ver serviços e versões:
nmap -sV -sC "<IP_DO_ALVO>"

Ver portas específicas:
nmap -p 22,80,443 "<IP_DO_ALVO>"

Salvar relatório:
nmap -sV -sC -oN "<ARQUIVO_DE_SAIDA.txt>" "<IP_DO_ALVO>"

Exemplo:
nmap -sV -sC -oN scan.txt 10.10.10.10

Use somente IP/portas dentro do escopo do CTF. Scan de todas as portas ou
opções agressivas só se o enunciado permitir.

J) HTTP / SITE
---------------
Ver somente headers:
curl -I "<URL_DO_DESAFIO>"

Ver headers e conteúdo:
curl -i "<URL_DO_DESAFIO>"

Seguir redirecionamentos:
curl -L "<URL_DO_DESAFIO>"

Salvar resposta em arquivo:
curl -L "<URL_DO_DESAFIO>" -o resposta.html

Buscar palavra na resposta:
curl -s "<URL_DO_DESAFIO>" | grep -iE 'flag|secret|token'

Ver robots.txt:
curl -i "<URL_DO_DESAFIO>/robots.txt"

Troque URL_DO_DESAFIO pela URL fornecida no CTF. Não use esses comandos contra
sites fora do escopo.

P) SERVIDOR HTTP TEMPORÁRIO PARA COMPARTILHAR ARQUIVO
-------------------------------------------------------
Se os dois computadores estiverem em uma rede que permita comunicação e a
política da FIAP autorizar:

1. No computador que tem o arquivo, entre na pasta dele:
   cd "<PASTA_QUE_CONTEM_O_ARQUIVO>"

2. Inicie servidor:
   python3 -m http.server 8000

3. Descubra o IP do computador:
   ip a

4. No outro computador, abra:
   http://<IP_DO_COMPUTADOR>:8000/<NOME_DO_ARQUIVO>

5. Ao terminar, volte ao terminal do servidor e pressione:
   Ctrl+C

A rede pode bloquear conexões entre dispositivos; isso não significa que o comando
esteja errado. Não exponha o servidor à internet nem compartilhe arquivos privados.
Para a prova, prefira Drive, e-mail institucional ou pendrive permitido.

Q) XAMPP NO LINUX (SE JÁ ESTIVER INSTALADO)
---------------------------------------------
Pasta web padrão:
  /opt/lampp/htdocs

Copiar arquivo para uma pasta do site:
  sudo mkdir -p /opt/lampp/htdocs/ctf
  sudo cp "<CAMINHO_DO_TXT>" /opt/lampp/htdocs/ctf/guia.txt

Iniciar Apache/XAMPP:
  sudo /opt/lampp/lampp start

Parar XAMPP:
  sudo /opt/lampp/lampp stop

Acessar no próprio computador:
  http://127.0.0.1/ctf/guia.txt

Para outro computador, use:
  http://<IP_DO_COMPUTADOR>/ctf/guia.txt

Isso depende de Apache ativo, IP acessível, firewall/rede permitindo e autorização.
Não abra portas do roteador nem exponha o computador pessoal à internet só para
a prova. Em rede campus, o acesso entre dispositivos pode ser bloqueado.

R) QUANDO O COMANDO DÁ ERRO
----------------------------
“command not found”
-> A ferramenta não está instalada ou não está no PATH. Use alternativa disponível.

“No such file or directory”
-> Confira pwd, ls e o caminho. Aspas ajudam se houver espaços.

“Permission denied”
-> Confira ls -l e usuário. Não tente sudo automaticamente; entenda o motivo.

“Could not resolve host”
-> Confira URL/domínio e DNS; talvez o host não esteja acessível.

“Connection timed out”
-> Pode ser rede, firewall, IP incorreto ou serviço indisponível.

“Permission denied” ao copiar para /opt/lampp/htdocs
-> É uma pasta do sistema. Só use sudo se for seu computador e você tiver
   autorização. No computador da FIAP, não altere configuração sem permissão.

18. NMAP: RECONHECIMENTO EM ALVOS DO CTF
======================================================================
Comece pelo escopo. Exemplos só para IPs explicitamente fornecidos:
  nmap -sT -sV --open <IP>
    -sT: conexão TCP normal; -sV: tenta identificar versão do serviço.
  nmap -Pn -sT -sV -p 22,80,443,445,8080 <IP>
    -Pn: não depende de resposta ao ping; -p: portas específicas.
  nmap -p- --open -T3 <IP>
    examina todas as portas TCP; use só se permitido e necessário.
  nmap -sC -sV -p 80,443 <IP>
    scripts padrão + versão nas portas indicadas.
  nmap -sU -p 53,161 <IP>
    testa UDP, geralmente mais lento; resultados podem ser inconclusivos.
  nmap -oN scan.txt -sV <IP>
    salva relatório legível.
  nmap -oA scan_ctf -sV <IP>
    salva formatos .nmap, .xml e .gnmap.

LEITURA DOS RESULTADOS:
  open = serviço aceitando conexões; closed = rejeitou; filtered = filtro.
  21 FTP, 22 SSH, 25 SMTP, 53 DNS, 80/443 HTTP(S), 139/445 SMB,
  3306 MySQL, 3389 RDP, 5432 PostgreSQL, 8080/8000 web alternativa.
  Porta aberta NÃO prova vulnerabilidade. Enumere serviço e versão antes.
  Se Nmap não existir: 'nc -vz <IP> <PORTA>' (Linux, se nc existir)
  ou 'Test-NetConnection -ComputerName <IP> -Port <PORTA>' (PowerShell).

19. METASPLOIT FRAMEWORK — GUIA DE LABORATÓRIO
======================================================================
Metasploit é um framework de módulos auxiliares, exploits e pós-exploração.
Use SOMENTE contra máquinas do desafio explicitamente autorizadas.

PRIMEIROS PASSOS:
  msfconsole -q                  abre console sem banner
  help                           lista comandos
  search type:auxiliary smb      procura módulos auxiliares SMB
  search name:eternalblue        procura módulos por nome
  search type:exploit platform:windows  filtra por plataforma
  info <NOME_DO_MODULO>          documentação e requisitos
  use <NOME_DO_MODULO>           seleciona módulo
  show options                   opções obrigatórias e valores atuais
  show advanced                  opções avançadas
  show targets                   alvos suportados, quando aplicável
  show payloads                  payloads compatíveis, quando aplicável
  set RHOSTS <IP>                IP do alvo do CTF
  set RPORT <PORTA>              porta do serviço
  set LHOST <SEU_IP_NO_LAB>      IP da máquina do participante no lab
  check                          testa vulnerabilidade, se módulo suportar
  run                            executa auxiliar/alguns módulos
  exploit                        executa módulo de exploit autorizado
  back                           volta à lista principal
  sessions                       lista sessões do laboratório
  sessions -i <ID>               interage com sessão do lab
  exit                           sai do console

EXEMPLO 1: ENUMERAÇÃO AUXILIAR SEM EXPLOIT
  msfconsole -q
  search type:auxiliary scanner/smb
  use auxiliary/scanner/smb/smb_version
  show options
  set RHOSTS <IP>
  run
  back
Objetivo: identificar implementação/versão SMB; isso NÃO explora o alvo.

EXEMPLO 2: ANALISAR UM MÓDULO ANTES DE QUALQUER EXECUÇÃO
  search name:ms17_010
  info exploit/windows/smb/ms17_010_eternalblue
  use exploit/windows/smb/ms17_010_eternalblue
  show options
  show targets
  show payloads
  set RHOSTS <IP_DO_LAB>
  check
NÃO execute exploit automaticamente: cheque SO, versão, arquitetura,
requisitos, regras do desafio e risco de travar a VM. 'check' pode ser
inconclusivo; nem todo módulo suporta check. Evite payloads persistentes.

SE APARECER 'NO SESSION WAS CREATED':
  - Pode não ser vulnerável, versão incompatível ou opções incorretas.
  - Confira 'show options', RHOSTS/RPORT, arquitetura e conectividade.
  - LHOST deve ser IP alcançável pelo alvo, não '127.0.0.1'.
  - Firewall/NAT podem impedir conexão de retorno.
  - Leia 'info' e procure o caminho menos invasivo permitido.

VOCABULÁRIO:
  exploit = código que aproveita falha; payload = ação após exploração;
  auxiliary = enumeração/testes; session = conexão estabelecida;
  RHOSTS = alvo; RPORT = porta alvo; LHOST = origem para retorno.

20. COMMAND INJECTION — LINUX E WINDOWS (WEB CTF)
======================================================================
Ocorre quando uma aplicação concatena entrada do usuário em um comando de
sistema sem tratamento adequado. Use SOMENTE endpoints de laboratório.

EXEMPLO DE CENÁRIO: formulário 'ping host' que chama comando do sistema.
TESTE MÍNIMO E NÃO DESTRUTIVO:
  127.0.0.1
  127.0.0.1; whoami       (shell Unix, se separador for interpretado)
  127.0.0.1 && id         (Unix, segundo comando só se primeiro funcionar)
  127.0.0.1 | whoami      (pipe Unix; depende do contexto)
  127.0.0.1 & whoami      (CMD Windows: separador de comandos)
  127.0.0.1 && whoami     (CMD Windows: executa se primeiro der certo)

INTERPRETAÇÃO:
  - Se aparecer usuário do processo web, há indício forte de execução.
  - Se o texto for mostrado literalmente, talvez esteja escapado.
  - Erro de sintaxe não prova ausência de falha; contexto importa.
  - Em Linux, 'id', 'pwd', 'uname -a' ajudam a identificar ambiente.
  - Em Windows, 'whoami', 'ver', 'cd' ajudam a identificar ambiente.
  - Não use comandos destrutivos, downloads de payloads ou persistência.

DIFERENÇAS IMPORTANTES:
  Bash: ; separa, && condicional, || se falhar, | pipe, $(...) substituição.
  CMD: & separa, && condicional, || se falhar, | pipe.
  PowerShell: ; separa; && só em PowerShell 7+, não no Windows PowerShell 5.1.
  URL: caracteres como & e # têm significado especial; use URL encoding
  quando o teste for em parâmetros HTTP, por exemplo %26 para '&'.

COMO INVESTIGAR:
  1) Encontre parâmetro que parece chegar ao SO (ping, host, file, path).
  2) Observe saída normal e mensagem de erro.
  3) Compare uma entrada legítima com teste mínimo 'whoami' ou 'id'.
  4) Confirme sistema operacional e contexto.
  5) Leia apenas arquivos indicados pelo desafio e registre evidências.
  6) Se não houver saída visível, analise tempo/erros com cautela;
     não faça tentativas indiscriminadas.

21. WEB CTF: CHECKLIST DE TESTES E INTERPRETAÇÃO
======================================================================
RECONHECIMENTO MANUAL
  - Veja HTML (Ctrl+U), DevTools (F12), abas Network/Storage/Console.
  - Procure comentários HTML, JS, endpoints, source maps, formulários.
  - Veja robots.txt, sitemap.xml, cookies e códigos de resposta.
  - Observe requisições Fetch/XHR e parâmetros ocultos.
  - Faça um teste de cada vez; anote requisição e resposta.

CURL PRÁTICO
  curl -i '<URL>'                    cabeçalhos + corpo
  curl -I '<URL>'                    cabeçalhos apenas (HEAD)
  curl -L -i '<URL>'                 segue redirects
  curl -X POST '<URL>/login' -d 'user=teste&pass=teste'
  curl -H 'Accept: application/json' '<URL>/api'
  curl -b 'session=VALOR' '<URL>'    envia cookie do laboratório
  curl -c cookies.txt '<URL>'       salva cookies recebidos
  curl -b cookies.txt '<URL>'       reutiliza cookies salvos
  curl --data-urlencode 'q=a b' '<URL>/search'
  curl -s '<URL>' | grep -Ei 'flag|TODO|secret|api'
  curl -v '<URL>'                    detalhes da conexão
No PowerShell prefira curl.exe com os mesmos argumentos.

STATUS HTTP
  200 OK; 301/302 redirecionamento; 400 entrada ruim;
  401 não autenticado; 403 proibido; 404 não encontrado;
  405 método não permitido; 500 erro do servidor.
Um 403 não é permissão para tentar burlar regras da competição.

SQL INJECTION: IDENTIFICAÇÃO NO LAB
  - Pistas: parâmetros numéricos, mensagens de banco, resposta alterada.
  - Compare valor normal e entrada com apóstrofo simples: '
  - Erro SQL após apóstrofo sugere consulta mal parametrizada, mas não prova.
  - Observe diferença de resposta e confirme em ambiente do desafio.
  - SQLi é distinta de command injection: uma afeta consulta ao banco;
    outra afeta comando do sistema operacional.
  - Se houver código-fonte, procure concatenação de SQL e uso de parâmetros.

XSS: RECONHECIMENTO
  - Insira um marcador textual único no campo e veja onde ele aparece.
  - Inspecione se o texto entra em HTML, atributo, JavaScript ou URL.
  - Contexto e encoding determinam se há vulnerabilidade.
  - Não use XSS para coletar sessões ou dados de outras pessoas.

PATH TRAVERSAL E LFI: RECONHECIMENTO
  - Pistas: 'file=', 'page=', 'template=', 'download='.
  - Observe se a aplicação concatena caminhos fornecidos pelo usuário.
  - Compare arquivo permitido com caminho relativo de teste dentro do lab.
  - Erros que mostram caminhos internos são pistas, não prova definitiva.

IDOR / AUTORIZAÇÃO
  - Compare acesso aos próprios objetos de teste em contas do laboratório.
  - Se alterar um ID permite ler recurso de outra conta de teste sem
    autorização, documente; não acesse dados reais de terceiros.

JWT (JSON WEB TOKEN)
  - Formato: cabecalho.payload.assinatura (3 partes separadas por pontos).
  - Header/payload são Base64URL, NÃO criptografia.
  - Examine 'alg', 'typ', 'sub', 'role', 'exp', 'iat', 'aud'.
  - Decodificar não valida assinatura nem permite editar token legitimamente.

23. WIRESHARK / TSHARK: ROTEIRO DE INVESTIGAÇÃO
======================================================================
ABRIR: File -> Open -> arquivo .pcap/.pcapng.
PASSO A PASSO:
  1) Statistics -> Protocol Hierarchy: quais protocolos predominam?
  2) Statistics -> Conversations: quais IPs conversam mais?
  3) Filtre 'dns' e procure domínios suspeitos.
  4) Filtre 'http' e veja GET/POST, Host, User-Agent, códigos HTTP.
  5) Clique no pacote -> Follow -> TCP Stream (ou HTTP Stream).
  6) Veja 'File -> Export Objects -> HTTP' se houver objetos.
  7) Se houver TLS, payload pode estar cifrado; analise metadados.
  8) Pesquise padrões de flag, credenciais fictícias e nomes de arquivo.

FILTROS DE EXIBIÇÃO (barra do Wireshark)
  ip.addr == <IP>                  origem OU destino
  ip.src == <IP>                   só origem
  ip.dst == <IP>                   só destino
  tcp.port == 80                  porta TCP
  udp.port == 53                  porta UDP
  dns                             DNS
  dns.qry.name contains "ctf"     consulta contendo texto
  http                            HTTP
  http.request.method == "POST"    só POST
  http.response.code == 200       respostas 200
  http.host contains "lab"        host HTTP com texto
  tcp.stream eq 0                 conversa TCP de índice 0
  tcp.analysis.retransmission     retransmissões
  frame contains "flag"           bytes contendo texto
  tls                             TLS
  icmp                            ICMP
  smb2                            SMB2
  ftp                             FTP
  !(arp or mdns)                  exclui ruído comum
Atenção: 'frame contains' encontra bytes; conteúdo TLS cifrado não aparece.

TSHARK (SE INSTALADO)
  tshark -r '<ARQUIVO>' -q -z io,phs
  tshark -r '<ARQUIVO>' -q -z conv,tcp
  tshark -r '<ARQUIVO>' -Y 'dns' -T fields -e dns.qry.name
  tshark -r '<ARQUIVO>' -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
  tshark -r '<ARQUIVO>' -Y 'frame contains "flag"'
  tshark -r '<ARQUIVO>' -q -z follow,tcp,ascii,0
A saída do follow depende de qual stream tem a informação; troque 0.

25. CRIPTOGRAFIA, ENCODING E HASHES
======================================================================
IDENTIFICAÇÃO:
  Base64: letras/números/+/, frequentemente '=' no final; Base64URL usa -_.
  Hex: caracteres 0-9 a-f, geralmente pares de dígitos.
  ROT13/Caesar: substituição de letras, sem segredo criptográfico.
  MD5: 32 hex; SHA1: 40 hex; SHA256: 64 hex (tamanho não é prova).
  XOR: bytes combinados com chave; padrões podem surgir após decodificação.

LINUX:
  printf 'SGVsbG8=' | base64 -d
  printf '48656c6c6f' | xxd -r -p
  printf 'hello' | sha256sum
  echo -n 'hello' | md5sum
  printf 'uryyb' | tr 'A-Za-z' 'N-ZA-Mn-za-m'

PYTHON 3 (WINDOWS OU LINUX)
  python3 -c "import base64;print(base64.b64decode('SGVsbG8=').decode())"
  python3 -c "print(bytes.fromhex('48656c6c6f').decode())"
  python3 -c "import codecs;print(codecs.decode('uryyb','rot_13'))"
  python3 -c "import hashlib;print(hashlib.sha256(b'hello').hexdigest())"
  python3 -c "s='abc';print(''.join(chr(ord(c)^1) for c in s))"
No Windows, se 'python3' falhar, tente 'py -3' ou 'python'.

BASE64URL JWT COM PYTHON:
  python3 -c "import base64,json; t='eyJhbGciOiJub25lIn0.eyJyb2xlIjoidXNlciJ9.'; p=t.split('.')[1];print(json.loads(base64.urlsafe_b64decode(p+'='*(-len(p)%4))))"
O exemplo só DECODIFICA payload de demonstração; não autentica token.

HASH NÃO É CRIPTOGRAFIA REVERSÍVEL. Em desafios de senha/hash, primeiro
identifique algoritmo e formato; use apenas dados fictícios do laboratório.

  -> identifique permissões -> examine recursos autorizados -> anote pistas.

31. TROUBLESHOOTING: QUANDO NADA FUNCIONA
======================================================================
'command not found' / 'não é reconhecido':
  - Verifique grafia e PATH: which/where/Get-Command.
  - Confira se programa existe. Não dependa de instalação no evento.
'permission denied' / 'acesso negado':
  - Verifique permissões; não tente contornar controles fora do desafio.
'connection refused':
  - Host respondeu, mas porta não aceita; confira IP/porta/serviço.
'connection timed out':
  - Pode ser firewall, rota, serviço indisponível; confira escopo e rede.
'no route to host':
  - Problema de roteamento/conectividade; verifique IP/rota/VPN do lab.
'404':
  - Recurso não encontrado; revise caminho e capitalização.
'403':
  - Acesso proibido; examine autenticação/permissões do desafio.
'500':
  - Erro no servidor; compare requisições e consulte mensagens do lab.
'base64: invalid input':
  - Verifique espaços, padding, Base64URL e se dado é realmente Base64.
'Wireshark não mostra HTTP':
  - Talvez seja HTTPS/TLS, porta diferente ou protocolo encapsulado.
'Nmap mostra filtered':
  - Pode haver firewall; não significa serviço vulnerável.

ADENDO ESPECÍFICO BIN E PDF
==============================================================================
CTF FIAP — ADENDO PRÁTICO: ARQUIVOS .BIN E .PDF
================================================
Guia de triagem, análise e transferência Windows físico -> Kali VM.
Uso apenas em desafios e laboratórios autorizados. Preserve os arquivos originais.

1) PRIMEIRO: TRANSFERIR DO WINDOWS (XAMPP) PARA A KALI
-----------------------------------------------------
No Windows físico:
  ipconfig
  # Anote o IPv4 do adaptador acessível pela Kali.
  # Abra XAMPP Control Panel e clique Start em Apache.
  # Coloque desafio.bin e desafio.pdf em C:\xampp\htdocs\ctf\
  # Teste no navegador do Windows: http://localhost/ctf/desafio.pdf

Na Kali:
  ip -br addr
  ip route
  ping -c 4 IP_DO_WINDOWS
  curl -I http://IP_DO_WINDOWS/ctf/desafio.pdf
  mkdir -p ~/ctf && cd ~/ctf
  wget http://IP_DO_WINDOWS/ctf/desafio.bin
  wget http://IP_DO_WINDOWS/ctf/desafio.pdf
  ls -lh
  file desafio.bin desafio.pdf

Substitua IP_DO_WINDOWS e nomes de arquivos. Se Apache usar porta 8080,
utilize http://IP_DO_WINDOWS:8080/ctf/desafio.bin.
Erro 404 = caminho/nome errado; 403 = acesso negado; connection refused =
Apache/porta indisponível; timeout = rota/firewall/rede. Ping pode estar bloqueado.
Não desative o firewall sem autorização. Compare SHA256 na origem e destino:
  # Windows CMD: certutil -hashfile C:\xampp\htdocs\ctf\desafio.bin SHA256
  # Kali:        sha256sum desafio.bin

2) BIN — TRIAGEM INICIAL
-----------------------
  file desafio.bin
  ls -lh desafio.bin
  stat desafio.bin
  sha256sum desafio.bin
  xxd -l 256 desafio.bin
  strings -a -n 5 desafio.bin | head -n 100
  strings -a desafio.bin | grep -iE 'flag|ctf|fiap|https?://|password|key'
  binwalk desafio.bin

EXPLICAÇÃO:
  file: identifica assinatura/tipo real; extensão .bin não define o formato.
  ls/stat: tamanho e datas; sha256sum: impressão digital para integridade.
  xxd: mostra bytes hexadecimais; cabeçalho pode indicar ZIP, PDF, PNG, ELF etc.
  strings: procura sequências legíveis; grep filtra termos importantes.
  binwalk: procura assinaturas de formatos dentro do arquivo; resultados podem
  ser falsos positivos. Não extraia ou execute cegamente conteúdo desconhecido.

Se o arquivo for ZIP ou outro contêiner, liste antes de extrair:
  unzip -l desafio.bin
  7z l desafio.bin
Se for executável ELF ou PE, faça análise ESTÁTICA, não execute:
  objdump -x desafio.bin | head -n 100
  strings -a desafio.bin | grep -iE 'cmd.exe|powershell|http|AppData|/bin/sh'
Se for memória RAM do Windows e Volatility 3 estiver instalado:
  vol -f desafio.bin windows.info
  vol -f desafio.bin windows.pslist
  vol -f desafio.bin windows.pstree
  vol -f desafio.bin windows.cmdline
  vol -f desafio.bin windows.netscan
  vol -f desafio.bin windows.filescan
  # Alguns plugins dependem da imagem e símbolos disponíveis.
Se for firmware ou arquivo desconhecido, use 'file', 'xxd', 'binwalk' e o
ENUNCIADO para decidir o próximo passo. Não assuma que todo BIN é memória.

3) PDF — TRIAGEM E FORENSE
-------------------------
  file desafio.pdf
  pdfinfo desafio.pdf
  exiftool desafio.pdf
  pdftotext -layout desafio.pdf texto.txt
  less texto.txt
  grep -niE 'flag|ctf|fiap|senha|password|http' texto.txt
  pdfdetach -list desafio.pdf
  strings -a desafio.pdf | grep -iE '/JavaScript|/JS|/OpenAction|/EmbeddedFile|/URI'
  qpdf --check desafio.pdf

EXPLICAÇÃO:
  pdfinfo: páginas, autor, produtor, datas e criptografia (quando disponíveis).
  exiftool: metadados adicionais; metadados podem ser ausentes ou manipulados.
  pdftotext -layout: extrai texto e tenta manter colunas; PDF digitalizado pode
  não ter texto extraível (nesse caso, inspecione as páginas visualmente).
  grep -niE: procura pistas, mostrando número da linha.
  pdfdetach -list: lista arquivos anexados ao PDF, sem executá-los.
  strings + grep: procura indicadores de scripts, links, anexos e ações.
  qpdf --check: verifica a estrutura do PDF; pode não estar instalado.

Se houver anexos e o desafio autorizar extração:
  mkdir -p anexos
  pdfdetach -saveall -o anexos desafio.pdf
  # Verifique a ajuda da versão instalada: pdfdetach -h
  # Nunca execute anexos desconhecidos no computador físico.

Se o PDF estiver protegido por senha, primeiro procure pistas no enunciado,
metadados e arquivos relacionados. Não tente quebrar proteção fora do escopo.

4) QUANDO O PDF E O BIN VÊM JUNTOS
--------------------------------
Hipóteses úteis, mas NÃO garantidas:
- O PDF contém instruções/senha para interpretar o BIN.
- O BIN guarda uma imagem, memória, arquivo compactado ou evidência citada no PDF.
- O PDF é o enunciado e o BIN é o artefato principal.
Passos:
  1. pdfinfo e pdftotext no PDF; leia o enunciado integral.
  2. file, sha256sum, xxd e strings no BIN.
  3. Compare nomes, datas, hashes, IPs, URLs e termos presentes nos dois.
  4. Escolha a ferramenta específica somente após identificar o formato.
  5. Confira se a resposta pede flag, processo, IP, domínio, hash ou horário.

5) MINI-REFERÊNCIA WINDOWS
-------------------------
CMD:
  dir /a
  ipconfig
  certutil -hashfile desafio.bin SHA256
PowerShell:
  Get-ChildItem -Force
  Get-FileHash .\desafio.bin -Algorithm SHA256
  Get-Item .\desafio.pdf | Format-List *

6) COMO PEDIR AJUDA DURANTE O CTF
--------------------------------
Envie o enunciado COMPLETO e os arquivos ORIGINAIS .bin/.pdf, se as regras
permitirem, ou cole a saída de:
  file desafio.bin
  ls -lh desafio.bin
  xxd -l 64 desafio.bin
  pdfinfo desafio.pdf
Diga o formato exato da resposta esperado. Não invente flags: valide as pistas.
